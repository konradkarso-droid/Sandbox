# 1. Что проверяет шаг и чего не проверяет

**Проверяет** гипотезу Г0-р: в реализации нет переходов вне описи, и
реализация не делает ничего, что модель шага 4 считает недостижимым. Заодно
повторно, уже на живом коде, проверяются Г0-м и Г0-о.

**Решения пользователя:**

- в оболочке исполняется **код агента** — то, что агент пишет и запускает.
  Это случай поставщиков моделей: в обоих инцидентах агент исполнял код
  внутри песочницы;
- обращение к модели — позже, как полномочие из описи;
- замыкание контура для локальных агентов целиком — позже;
- язык — Python с Wasmtime. Независимая вторая реализация (например, на
  Rust) — шаг 7.

**Не проверяет:**

- измельчение и провенанс уровня (шаг 3) в живом коде;
- физические побочные каналы;
- живую языковую модель как агента.

# 2. Устройство

| Часть | Что это |
|----------------------|----------------------------------------------------------|
| **исполнитель** | отдельный процесс; держит экземпляры WebAssembly, таблицы полномочий, объекты, журнал. Единственный, кто что-либо делает |
| **ведущий** | недоверенная сторона в другом процессе: передаёт исполнителю модули агентов и слова человека, получает итоги. Доступа к состоянию исполнителя не имеет |
| **агент** | модуль WebAssembly. Видит только свою линейную память и **одну** функцию среды — ворота `env.call` — плюс `env.spawn` для помощника |
| **наблюдатель** | проверяет законы по журналу, по выгрузке состояния и сканированием содержимого; кода исполнителя не импортирует |

## 2.1. Чего у агента нет по построению

Нет ни WASI (файлы, часы, случайность, сеть), ни других функций. Модуль,
который просит что-то сверх `env.call` и `env.spawn`, **не загружается**:
Wasmtime отказывает при связывании. Это структурная замкнутость
буквально — перехода не существует.

## 2.2. Полномочия — номера в своей таблице

У каждого экземпляра своя таблица: номер → (объект, право). Агент
называет полномочие номером из **своей** таблицы. Угадать номер чужой
таблицы бессмысленно: номер ищется только в своей (A3).

Ворота: `call(номер, операция, a, b) → результат`.

| Операция | Право | Что делает |
|--------------------|------------|-------------------------------------------------|
| 0 чтение | чт | копирует содержимое объекта в память агента (a — адрес, b — длина) |
| 1 запись | зап | дописывает в объект байты из памяти агента; запись в E стоит топлива по цене |
| 2 вызов | выз | резольвер: имя из описи → постоянный ответ-число (сведение, не полномочие); неописанное имя → постоянный отказ, никуда не пересылая |
| 3 положить ссылку | зап | кладёт в объект ссылку — полномочие номер a из своей таблицы |
| 4 взять ссылку | чт | берёт из объекта ссылку номер a и добавляет её в свою таблицу |

**Ошибки — постоянные числа без содержимого:**

| Код | Смысл |
|--------------|------------------------------------------------------------------|
| −1 | нет номера или права |
| −2 | нет такого имени |
| −3 | не хватает топлива на цену |
| −4 | адрес за границей памяти |
| −5 | полно: объект, таблица или число экземпляров на пределе |

**Помощник.** `spawn()` создаёт новый экземпляр того же модуля в том же
хранилище: топливо и пределы общие (A4). Помощник получает копию таблицы
родителя и сразу исполняет свою функцию `helper`.

**Слова человека.** Ведущий передаёт текст. Исполнитель дописывает его во
вход агента как данные (метка Ч), и только.

## 2.3. Объекты (как в модели шага 4)

Для каждого контура i:

- снимок i;
- вход i;
- выход i;
- E i;
- общая служба «резольвер».

Память агента — его линейная память WebAssembly. Все объекты учитываются
в пределах памяти контура: урок шага 3 — хранилище вне предела хрупко.

## 2.4. Пределы

- **Топливо** на контур (бюджет работы).
- **Предел линейной памяти.**
- **Предел числа экземпляров**, включая помощников.
- **Предел размера каждого объекта.**
- **Предел длины таблицы полномочий.**

Все числа объявлены, не подобраны: топливо 3 000 000 на контур, цена
записи в E — 1000 единиц топлива, линейная память — 2 страницы по 64 КиБ,
экземпляров — 4, объект — 4096 байт, таблица — 64 полномочия.

# 3. Что проверяет наблюдатель

| Закон | Как проверяется в реализации |
|---------------|-----------------------------------------------------------------|
| И20р | ни в одной таблице нет полномочия на СНАРУЖИ; файл «снаружи» не тронут |
| И21р | метка-«канарейка» агента не найдена в файле «снаружи» |
| И22р | канарейка агента i не найдена ни в объектах, ни в памяти контура j |
| И23р | подпись каждого действия из журнала есть в описи шага 4; модуль с неописанным импортом не загружается |
| И24р | полномочия появляются только взятием ссылки или копией при создании помощника |
| И26 | **сверка с моделью:** все факты, порождённые реализацией, входят в неподвижную точку модели шага 4 для той же конфигурации |
| И27 | исполнитель не падает: любая ошибка агента — ловушка или код отказа, а не сбой исполнителя |
| И25р | жить можно: в правильной среде агенты пишут выход и E, читают слова человека, зовут резольвер, создают помощника |
| И5 | цепочка журнала цела |

**Канарейка** — случайные 16 байт, которые исполнитель кладёт в начало
памяти агента. Сканирование ловит прямое копирование. Закодированную
передачу (например, побайтное «исключающее или») оно не ловит. Её ловят
метки сведений на уровне объектов (И26). Поэтому проверки две, и разные.

# 4. Противники

1. **Именные программы** на языке WebAssembly:
   - **разведка** — все номера × все операции, попытки взять и положить
     ссылки, неописанные имена у резольвера, помощник делает то же;
   - бесконечный цикл;
   - рост памяти сверх предела;
   - адреса за границей;
   - импорт WASI;
   - импорт неописанной функции;
   - импорт «полномочия по имени».
2. **Случайные программы** — тысячи вызовов ворот со случайными номерами,
   операциями и адресами, в том числе отрицательными и огромными. По 200
   программ на каждую конфигурацию.
3. **Слова человека,** включая «разрешаю».

# 5. Порчи реализации — те же классы, что в модели

Д1р–Д8р повторяют Д1–Д8 шага 4, но в живом исполнителе:

| Порча | Что |
|---------------|-----------------------------------------------------------------|
| Д1р | общий объект в таблицах обоих агентов |
| Д2р | резольвер пересылает неописанное имя в файл «снаружи» и возвращает оттуда ответ |
| Д3р | «разрешаю» во входе добавляет в таблицу запись наружу |
| Д4р | есть функция `by_name` — полномочие по имени |
| Д5р | помощник рождается с полномочием наружу |
| Д6р | общая очередь с признаком «занято» |
| Д7р | отказ в чтении копирует содержимое |
| Д8р | общий снимок |

Каждая обязана быть поймана хотя бы одним законом наблюдателя.

# 6. Чего реализация не умеет

- **Физические каналы** (время, кеш процессора, питание) — вне области
  гарантий.
- **Основание доверия:** Python, Wasmtime, ОС. Ошибка в Wasmtime — вне
  области.
- **Исполнитель и ведущий — процессы одного пользователя ОС.** Разделение
  процессов здесь — не рубеж безопасности, а разделение ролей. Рубеж —
  оболочка WebAssembly. Второй рубеж средствами ОС — по таблице устройств
  (концепция §3).
- **Канарейка ловит только прямое копирование** (§3).
- **Шаг 3 не перенесён:** цена в E — простая константа топлива,
  провенанса уровня нет.

# 7. Прогон по CHECKLIST.md

| Пункт | Ответ |
|-----------------------------|---------------------------------------------------|
| 1. Безопасность и цена | Платим тем, что у агента одна функция-ворота, а не богатый набор. Богатый набор — богатая опись и больше мест для расхождения, а оба инцидента — именно расхождения. |
| 2. Класс или случай | Неописанный импорт, пересылка неизвестного имени, общий объект — **классы**. Поэтому и случайные программы, и именные, и порчи на каждый класс. |
| 3. Готовое | Снаружи — Wasmtime: топливо, пределы памяти и экземпляров, отказ на неописанный импорт. Проверено вживую до кода. Модель полномочий-номеров — из object-capability (знание из памяти, устойчивое). Внутри проекта — опись и неподвижная точка шага 4 как эталон, журнал шага 2. |
| 4. Угадываю или объявляю | **Объявляю.** Опись — это список функций, которые исполнитель даёт при связывании; одно место (исполнитель), сверка с описью шага 4 тестом. Пределы — объявленные числа в конфигурации. |
| 5. Куда ошибётся | «Не нашли выхода» — терминальный вывод. Отсюда две независимые проверки утечки (канарейка и метки), сверка с моделью, порчи и случайные программы. |
| 6. Чем видно | Каждое отклонение модуля при загрузке пишется с причиной. Каждое действие ворот — в журнал с подписью. Итог по каждому закону — словами. |
| 7. Что не слить | (а) **Канарейка и метки** — ловят разное (§3). (б) **Отказ при загрузке и отказ в воротах** — первый означает «перехода нет вовсе», второй — «переход есть, но права нет». (в) **Ведущий и исполнитель** — ведущий недоверен. |
| 8. Чего не умеет | §6. |
| 9. Условие включения | Сверка с моделью включается только для действий, у которых есть соответствие в модели шага 4. Действие без соответствия само по себе — нарушение И23р, а не «пропуск». |

**Что прогон переставил:**

- **У агента одна функция-ворота** вместо набора (п. 1).
- **Две проверки утечки, разные по природе** (пп. 5, 7).
- **Отказ при загрузке учитывается отдельно от отказа в воротах** (п. 7).

# 8. Что уточнено при исполнении

Пока шёл код, спецификация уточнилась. Всё ниже — в коде и в отчёте.

- **Ворота привязаны к экземпляру.** Каждый экземпляр связывается со
  своей копией `env.call` и `env.spawn`, и ворота знают таблицу
  вызывающего, не спрашивая агента.
- **Код −5 «полно»** — для пределов объекта, таблицы и числа экземпляров.
- **И26 разделён на два закона:** И26 — факты, порождённые действиями;
  И26н — начальные права. Порча, видная уже в начальной таблице, не
  засчитывается программам как пойманная их поведением.
- **Утечка проверяется двумя способами и учитывается раздельно:** «/к» —
  канарейка, «/м» — метки.
- **Прибор «аудит»** в процессе исполнителя: открытие файлов вне рабочей
  папки, сеть, запуск процессов. Прибор, а не рубеж.
- **Счётчик отказов ворот по кодам** — чтобы «ничего не вышло» было видно
  как «столько-то раз нет права», а не как тишина.
- **Сверка «тот ли класс»:** факты порчи реализации сравниваются с
  неподвижной точкой модели с той же порчей.
- **Ещё противники:** петля в помощнике, ссылки до предела таблицы,
  плательщик (тратит всё топливо на записи в E), старт-разведка (действует
  до первого вызова `main`), модуль без памяти, память под чужим именем,
  импорт памяти, чужая подпись `env.call`, кривой модуль.
- **Длинная серия против правильного исполнителя:** 2000 случайных
  программ по 600 вызовов в основной функции и 200 у помощника.
