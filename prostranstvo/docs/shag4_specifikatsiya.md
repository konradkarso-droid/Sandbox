# 1. Что проверяет шаг и чего не проверяет

**Проверяет** звено Л0 в модели: гипотезы Г0-м (пути наружу нет при
любом бюджете) и Г0-о (основы не меняются изнутри, в том числе словами
человека). Плюс требование «жить можно»: замкнутость не должна держаться
на том, что агенту запрещено всё.

**Не проверяет:**

- реализацию (Г0-р) — шаг 5;
- цену и бюджет: в этом шаге их нет вовсе, потому что замкнутость от
  бюджета не зависит по определению;
- физические побочные каналы: вне области гарантий.

# 2. Что известно снаружи

*(сверено 12.11.2026)*

- **Харрисон, Руццо, Ульман (1976).** В общей модели прав вопрос «может
  ли право когда-нибудь утечь» неразрешим. Разрешим он в узких классах:
  когда каждая команда состоит из одной элементарной операции, и когда
  нельзя создавать новых субъектов и объектов (тогда задача
  PSPACE-полна).
- **Модель Take-Grant.** Безопасность в ней разрешима за линейное время
  даже при неограниченном числе создаваемых объектов.

**Вывод для среды.** Доказать «выход недостижим в принципе» можно только
для среды, правила которой **сознательно взяты из разрешимого класса**.
Это требование к самой среде, а не только к проверке. Здесь класс такой:
все правила **монотонны** — права и сведения только добавляются, ни одно
правило не требует отсутствия чего-либо.

# 3. Мир шага 4

## 3.1. Кто действует

**Субъекты:**

- два агента, а1 и а2, — у каждого свой контур;
- у каждого — помощник (п1, п2).

Помощник появляется, когда агент его создаёт, и получает копию полномочий
родителя. Помощников может быть сколько угодно, но все они одинаковы,
поэтому одного на агента достаточно (§7).

## 3.2. Объекты

| Объект | Чей | Что это |
|---|---|---|
| память1, память2 | агента | рабочее состояние |
| снимок1, снимок2 | агента | хранилище снимков |
| вход1, вход2 | агента, пишет человек | слова человека агенту |
| выход1, выход2 | агента | разрешённый вывод человеку |
| E1, E2 | агента | защищённые объекты внутри контура |
| резольвер | общая служба | отвечает только на имена из описи |
| СНАРУЖИ | — | всё вне контура: сеть, ОС, другие системы |

## 3.3. Сведения и полномочия

- **Сведения** — метки происхождения на объектах: А1, А2 (сведения
  агентов), Ч (слова человека), С (сведения снаружи).
- **Полномочие** — право субъекта на объект: чтение, запись или вызов.
  Полномочие можно положить в объект, на который есть запись. Кто прочтёт
  этот объект, получит полномочие — так передаются ссылки.

## 3.4. Правила правильной среды

**Опись** — полный перечень правил:

1. **Чтение.** Есть право чтения объекта → сведения объекта попадают в
   память читающего; полномочия, лежащие в объекте, — к читающему.
2. **Запись.** Есть право записи → сведения памяти пишущего попадают в
   объект; можно положить в объект любое своё полномочие.
3. **Создание помощника.** Помощник получает копию полномочий родителя и
   ничего сверх них.
4. **Слова человека.** Человек пишет во вход агента. Это **данные**:
   метка Ч на входе, и больше ничего.
5. **Резольвер.** Отвечает на имена из описи постоянным ответом. На
   неописанное имя — постоянный отказ, никуда не пересылая.

**Начальные полномочия агента i:**

- память i — чтение и запись;
- снимок i — чтение и запись;
- выход i — запись;
- E i — запись;
- вход i — чтение;
- резольвер — вызов.

**Ни у кого нет полномочия на СНАРУЖИ.**

# 4. Законы шага 4

| Закон | Формулировка | Гипотеза |
|---|---|---|
| И20 | ни у одного субъекта внутри нет полномочия на СНАРУЖИ | Г0-м |
| И21 | сведения агентов (А1, А2) не попадают СНАРУЖИ | Г0-м |
| И22 | сведения одного агента не попадают в память другого | Г0-м (контуры агентов разделены) |
| И23 | каждое сработавшее правило с его объектом есть в описи | Г0-м, A11 |
| И24 | полномочия появляются только чтением переданной ссылки или копией родителя при создании помощника | Г0-о, A10 |
| И25 | **жить можно:** каждый агент может писать в свой выход и свой E, читать слова человека, создать помощника, звать резольвер | Л5 |

**Почему И25 обязателен.** Среда, где агенту запрещено всё, тоже
«замкнута». Но она бесполезна, и её замкнутость ничего не доказывает.

# 5. Порчи — классы реальных инцидентов

| Порча | Что | Класс (концепция §27) | Обязана сработать |
|---|---|---|---|
| Д1 | общий объект, куда пишут и откуда читают оба агента | доска объявлений в хранилище пакетов (июль 2026) | И22, И23 |
| Д2 | резольвер на неописанное имя пересылает запрос наружу и возвращает ответ | выход через DNS (сентябрь 2026) | И21, И23 |
| Д3 | слова человека «разрешаю» дают агенту полномочие наружу | основы меняются словами (A10) | И20, И24 |
| Д4 | полномочие выдаётся по имени объекта | окружающее полномочие (A3, A11) | И20, И24 |
| Д5 | помощник рождается с полномочием наружу, которого нет у родителя | усиление при создании помощника | И20, И24 |
| Д6 | общая очередь, где один агент видит «занято» от другого | скрытый канал через общий ресурс | И22, И23 |
| Д7 | отказ в чтении пересказывает содержимое объекта | утечка через ошибку (О6) | И22, И23 |
| Д8 | снимки обоих агентов в одном хранилище | общее хранилище | И22, И23 |

Отдельно — **не порча, а граница области**: «человек-ретранслятор»
переписывает выход одного агента во вход другого. Путь между контурами
через человека обязан найтись. Он записывается как «вне области
гарантий», а не как дефект среды.

# 6. Метод

**Все правила монотонны**, поэтому множество всего, что достижимо любой
последовательностью действий любой длины, — это **неподвижная точка**:
применять правила, пока ничего нового не появляется. Это и есть «при
любом бюджете и любых усилиях»: точка включает всё, что вообще можно
получить.

Два независимых вычислителя:

1. **Общий.** Правила записаны данными (табличка «если … то …»). Для
   каждого полученного факта хранится, каким правилом и из чего он
   выведен. По этому собирается путь-объяснение к нарушению.
2. **Прямой.** Те же правила, написанные циклами вручную, без таблички.

Неподвижные точки обоих обязаны совпасть для всех вариантов.

# 7. Чего модель не умеет

- **Отзыва прав и удаления нет.** Правила только добавляют. Это
  **завышает** возможности агента: в модели он может больше, чем в среде
  с отзывом. Для доказательства замкнутости это в запас: если наружу нет
  пути без отзыва, его нет и с отзывом. Оговорка: это верно, пока ни одно
  правило среды не требует отсутствия чего-либо.
- **Число помощников.** Помощник получает только копию полномочий родителя,
  поэтому любое их число даёт те же факты, что и один. Это рассуждение,
  а не перебор.
- **Сведения — метки, а не количество.** Сколько бит утекло, модель не
  считает; считает только, утекло ли.
- **Физические каналы** (время, кеш, питание) не моделируются — вне
  области гарантий. Логический скрытый канал (общая очередь, Д6) —
  моделируется.
- **Человек вне контура.** Его можно уговорить; модель показывает путь
  через него (ретранслятор), но не закрывает его.
