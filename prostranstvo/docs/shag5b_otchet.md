# Итог

**Цена защищённого эффекта в живом коде — ровно та, что в модели.**

- Путь наименьшей работы из точного поиска шага 3 исполнен через живой
  исполнитель. Он потратил ровно W_E работы и доставил E. Так в четырёх

- **Ни одна программа не доставила E дешевле W_E.** Ни свидетель, ни
  жадный, ни мошенник, ни сотни случайных. Закон И28 держится во всех
  запусках правильного исполнителя.
- **Граница точная.** Цена E = W_E + c:
  - при бюджете W_E (на единицу меньше) E не доставил никто;
  - при бюджете W_E + 1 свидетель доставил;

    бюджета.

  доставлен ни разу при бюджете 60.

**Учёт держится при настоящих сбоях.** 68 сбоев по инъекции во всех десяти
точках протокола, включая сбой посреди восстановления. Сбой — это смерть

**Сверка с моделями в обе стороны — без расхождений:**

- **модель шага 1 → живой код:** 100 путей модели, 2662 состояния

## 3.2. Учёт под сбоями

**Сбой — настоящий.** Процесс исполнителя завершается немедленно в точке
сбоя. Агент гибнет вместе с ним: он живёт в том же процессе. Новый процесс
восстанавливает остаток, расход и уровень по журналу. Каждое неоплаченное
— «потеряно», каждое доставленное — «завершено». Повторно не доставляется
ничего.

68 сбоев в серии правильного исполнителя:

| Точка | Сбоев |
|--------------------------------------------------------|------------------------|
| в начале фиксации | 8 |
| перед списанием | 8 |
| запись списания оборвана | 8 |
| после списания | 12 |
| запись доставки оборвана | 8 |
| после доставки | 8 |
| перед работой | 4 |
| запись работы оборвана | 4 |
| после работы | 4 |
| посреди восстановления | 4 |

Нарушений — 0. Пересчитанный после сбоя узел совпадает с прежним: секрет
переживает восстановление (тест).

**Разбитый журнал останавливает исполнитель.** Подмена одной записи
посреди журнала — исполнитель отказывается подниматься (тест).

## 3.3. Сверка с моделями

| Направление | Объём | Расхождений |
|-------------------------|----------------------------------|---------------------|
| модель шага 1 → живой код | 100 путей, 2662 состояния после каждого хода, 297 сбоев | 0 |
| модель шага 3 → живой код | 104 пути, 4629 ходов | 0 |
| живой код → модель шага 3 (И29) | каждое событие узлов каждого запуска | 0 в правильном исполнителе |
| живой код → модель шага 1 (И30) | запуски, где были только «А» и «Б» | 0 в правильном исполнителе |

**Как сверяется модель шага 1:**

- путь модели (только основной работник, без пакета) разбивается на
  «жизни» исполнителя — до сбоя или перезапуска;
- каждая жизнь — программа, один ход — один запуск;
- исход модели «сбой → ничего» — инъекция в начале фиксации;
- «сбой → списано, не доставлено» — после списания;
- после каждого хода сравниваются:
  - остаток;
  - расход;
  - получатель;
  - сводка журнала.

**Что сверка поправила ещё на проектировании.** В модели исход «сбой →
ничего» есть и у попытки, которая кончилась бы отказом. В первой версии
протокола первая точка сбоя стояла после проверки, и такой исход был
недостижим. Добавлена точка «в начале фиксации» — как в шаге 2.

**Р2р прячется, если сбой пришёлся на первую фиксацию.** Номер фиксации
исполнитель после сбоя восстанавливает по журналу. Доставка мимо журнала
оставляет свой номер «свободным», и следующая фиксация занимает его же.

обязательно выдаст ещё раз.

Порчи учёта случайные находят часто.

# 4. Остаётся гипотезой

- **Пределы испытанного.** Наблюдение, не доказательство. Один язык
  (Python), один движок (Wasmtime). Независимая реализация — шаг 7.
- **Агент не переживает сбой исполнителя.** Это свойство устройства: агент
  живёт в процессе исполнителя. Случай шага 2 «исполнитель упал, агент
  жив» здесь не воспроизводится.
- **Долей у помощников нет.** Бюджет общий на контур. Сверка с моделью
  шага 1 — только для основного работника.
- **Пакета нет.**
- **Цена работы объявлена.** Сколько это в секундах и джоулях — шаг 8.
- **Случайный оракул.** Результат узла — хеш с секретом. Без секрета у
  узла была бы прямая формула (С1 шага 3). Законные сокращения С1 и С2 в
  живом коде не проверялись: это свойства функции узла, а не
  исполнителя.
- **Наблюдатель знает таблицы и память со слов исполнителя.** Учёт он
  проверяет по своим файлам: журнал, получатели. Память узлов
  восстанавливает сам.
- **Телефон.** Не запускалось.

# 5. Откуда берётся каждая стоимость

| Что | Значение | Откуда |
|----------------|----------------------------|-------------------------------------|
| работа узла | 1 | объявлена, как в шаге 3 |
| фиксация | c = 1 | объявлена |
| неудачная фиксация | c_отк = 1 | объявлена |
| бюджет | 40; окно — W_E и W_E + 1 | объявлен |
| граф, K, M | из шага 3 | объявлены |
| **W_E** | 17 (K = 4), 57 (K = 5) при M = 4 | **вынуждено** провенансом и памятью; найдено точным поиском, в живом коде совпало |
| **цена E** | **W_E + c** | следует из двух предыдущих строк; граница подтверждена окном бюджета |
| топливо | 3 000 000 на контур | объявлено; к цене E отношения не имеет |

**Что объявлено, а что вынуждено** — как в шаге 3:

- число шагов N = 2ᴷ − 1 объявлено правилом измельчения;
- пересчёт сверх N вынужден памятью;
- провенанс делает и то и другое неделимым и несбрасываемым — теперь и в
  живом коде.

# 6. Чему научил шаг

1. **Цена, найденная в модели, переносится в живой код точно,** если
   уровень берётся из журнала, а не из поля. Иначе (Ж1р) цена падает до
   «конуса» последнего узла: 4 работы вместо 17.
2. **Журнал защищает и номера.** Доставка мимо журнала даёт повтор номера,
   и неоплаченное прячется за оплаченным (Р2р).
3. **Сверка с моделью — самостоятельный закон.** Ж5р не видит ни один
   закон учёта, а сверка видит сразу.
4. **Модель учит протокол.** Исход модели «сбой → ничего» у отказной
   попытки потребовал точку сбоя до проверки.
5. **Два ресурса не мешают друг другу.** Топливо кончается — ловушка.
   Бюджет кончается — отказ с кодом. Одно в другое не переливается.
