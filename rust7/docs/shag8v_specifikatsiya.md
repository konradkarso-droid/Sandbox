# 1. Зачем шаг

Шаг 8б проверил предел расхода телефона программами, которые нарочно
тратят как можно больше. Предел не удержался. Все дыры оказались одного
рода — **попытка без цены**:

| Что | Сколько за один контур |
|---|---|
| отказ ворот при пустом бюджете (−3), без записи | телефон: 268 мс и 266 мДж против предела 93 мс и 91 мДж |
| отказ фиксации при пустом бюджете: запись со сбросом на диск, плата 0 | сервер: 76 с и 133 МБ журнала |
| отказ не по деньгам («нет права», «нет ручки») — при любом остатке | сервер: 428 тысяч отказов, бюджет не тронут |

Это опровергает У4 концепции: «повторение расходует заново; бюджет
ограничивает число повторов».

**Решение владельца проекта:** сначала закрыть пустой бюджет — «нечем
заплатить, контур окончен», а оставшиеся отказы сделать платными
попытками. Делать то и другое одним шагом: что отказы останутся, уже
показал замер «отказы без права».

**Откуда правило.** Из исходных документов, а не придумано заново:

- **0.3, H14 и §46.1 п. 5** (концепция: У4): повторение расходует заново;
  бюджет ограничивает число повторов;
- **0.3, §48** (концепция: §10): ресурсная привязка нужна, чтобы
  ограничивать частоту и глубину поиска и делать повторные атаки
  конечными. Конец этого раздела в исходном PDF оборван и восстановлен
  при сведении;
- **0.1, §2 — «зеркало и аннигиляция»:** нулевой внешний след при
  ненулевой внутренней работе. Отказ при пустом бюджете сейчас устроен
  наоборот: след на диске есть, цены нет;
- **0.1, §3 и A5 — границы сеанса:** новый сеанс выдаёт только внешний
  контроллер. Бюджет кончился — сеанс окончен;
- **0.1, §8:** функции хоста тарифицируются отдельно;
- **решение шага 5б:** топливо — только на вычисления агента, бюджет — на
  работу среды. Отказ — работа среды: она проверяет вызов. Поэтому отказ
  платит бюджетом, а не топливом (вариант «топливо за обращение»
  отвергнут по этой причине).

**Не проверяет:**

- замкнутость: правила полномочий не меняются;
- цены успешных вызовов: они как в шаге 8б.

# 2. Правило

**Попытка** — каждый вызов `call` или `spawn` любым экземпляром контура:
агентом или помощником. Других путей к среде у агента нет: эти две функции
— вся опись того, что даётся при связывании (шаг 5).

**П1. Нечем заплатить — контур окончен.** Если в начале попытки остаток
бюджета контура ≤ 0:

- контур останавливается: пишется запись «останов» — одна на контур за
  жизнь исполнителя;
- вызов кончается ловушкой; исход `run` — «ловушка: бюджет исчерпан»;
- каждая следующая попытка этого контура сразу кончается той же
  ловушкой, без записи.

**П2. Отказ платит.** Попытка, которая кончилась отказом (отрицательный
возврат) и не записала свой отказ сама, платит min(g, остаток) и пишет
запись «отказ ворот». Свой отказ пишут фиксация, доставка узла и сдача
ответа — они уже платят min(c_отк, остаток), как с шага 5б.

**Стартовая функция помощника.** Пока помощник создаётся, плата 2g за
него уже списана, и остаток мог стать нулём только из-за неё. Попытка его
стартовой функции при остатке ≤ 0 не останавливает контур, а обрывает
создание: плата возвращается, `spawn` отвечает −3 и платит как отказ.
Ловушка движка в стартовой функции помощника тоже возвращает плату, но
обрывает весь вызов. Это место нашла вторая реализация; решение — в §16
контракта.

**Успешные вызовы** платят как в шаге 8б.

**Все цены ≥ 1.** С правилом включённым каждая цена — g, c, c_отк, цена
работы — не меньше 1. Иначе настройки отвергаются. Поэтому у каждой
попытки, которая не остановила контур, плата не меньше 1, и попыток за
контур не больше B.

**Порядок:**

1. П1: остаток ≤ 0 — останов;
2. всё как прежде;
3. отказ без своей записи — П2.

**Настройка** `paid_attempts`: 0 — прежнее поведение (по умолчанию), 1 —
правило включено. В запись «учёт» попадает, только если 1. При прежних
настройках журнал побайтно прежний.

**Вариант M0** (бюджет не ограничивает): остаток считается бесконечным,
П1 не срабатывает; П2 списывает g, бюджет уходит в минус, как и всё в M0.

# 3. Записи журнала

- «отказ ворот» для `call`: `{"kind": "отказ ворот", "contour": i,
  "subject": S, "call": "call", "cap": номер, "op": оп, "code": код,
  "charge": списано}`;
- для `spawn`: те же поля без `cap` и `op`, `"call": "spawn"`;
- «останов»: `{"kind": "останов", "contour": i, "subject": S, "why":
  "бюджет исчерпан"}`.

«Отказ ворот» — отдельный вид, а не «отказ»: у отказа фиксации есть номер
фиксации и получатель, и законы доставок (И4р) и проверки (П2п) читают
именно их. Слитые вместе, они начали бы принимать отказ ворот за отказ
фиксации.

# 4. Перебор попыток программой

Стратегии-противники шага 8б придумывались руками и пропустили самую
дорогую дыру. Теперь их даёт перебор (`experiments/enum8v.py`):

- все номера таблицы и номера вне неё, все операции, классы аргументов
  (верные, вне памяти, пустые, огромные), `spawn`;
- для `--kind 5б` и `6`, при полном и при малом остатке;
- для каждой попытки: код возврата, изменение расхода, какие записи
  появились, остановлен ли контур.

**Закон перебора (объявлен до прогона):** при включённом правиле нет ни
одной попытки, у которой расход не вырос и контур не остановлен. При
прежнем правиле такие попытки перечисляются — это мера дыры.

Каждый различимый класс попыток (код, записи) становится стратегией
«повторять, пока контур не остановится» — для сервера и для телефона.

# 5. Законы

| Закон | Что |
|---|---|
| И32р | каждая попытка с отказом оплачена: отказов в счётчике исполнителя (с последнего запуска) столько же, сколько записей «отказ ворот» и «отказ»; у «отказа ворот» плата g, кроме последней, после которой остаток 0 |
| И33р | после «останова» контура нет записей вызовов его агента и помощников до восстановления; «останов» — только при остатке ≤ 0; один на контур за жизнь исполнителя |
| И1р, И5р | расход включает плату «отказов ворот»; восстановление — тоже |
| молчание | при `paid_attempts` = 0 нет ни «отказа ворот», ни «останова» |

# 6. Окно бюджета и серия шага 6

- **Окно** — то же правило, что в шагах 6 и 8б. Отказов нет ни на честном
  пути, ни на самом дешёвом пути к E, поэтому ожидается B' = 625. Окно
  пересчитывается, а не берётся.
- **Серия шага 6** — по новым ценам и с правилом. Цели — те же десять, что
  в шаге 6, без новых. Если цель не выполнена — это результат, а не повод
  менять правило.

# 7. Предел для владельца

предел за жизнь контура = (B × p_b + F × p_f) × z, как в шаге 8б, с двумя
изменениями:

- **p_b — по всем видам платной работы, включая платные отказы,** и по
  самому дорогому из всех прогонов на телефоне. В шаге 8б фиксация между
  прогонами дорожала в 1,8 раза, а запас z = 1,5 объявлялся на разброс
  внутри одного прогона;
- **p_f — только чистые вычисления:** обращений к среде без платы больше
  нет.

Предел верен для тех состояний телефона, что наблюдались. Новое состояние
может дать больше — тогда предел пересчитывается по новому прогону.

**Вердикт на телефоне объявлен до прогона:** предел держится, если у
каждой стратегии перебора наибольшее время контура и энергия не больше
предела.
