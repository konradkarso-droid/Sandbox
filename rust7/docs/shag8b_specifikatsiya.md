# 1. Зачем шаг

Шаг 8 нашёл работу среды, за которую агент не платит: **вызов ворот**.
Каждый вызов оставляет запись «действие» в журнале со сбросом на диск. На
телефоне он стоит 0,37 мс и 0,34 мДж, а бюджета — 0. За топливо одного
контура агент может так потратить около 12 с и 11 Дж. Остальная работа
среды при бюджете 40 — не больше 58 мс.

**Решение владельца проекта:**

- платит агент, из бюджета (вариант 1);
- цены — по замеру, на шкале в 10 раз мельче (вариант Б);
- цена вызова — постоянная часть плюс плата за байты; плату за байты
  измерить;
- окно бюджета пересчитать тем же правилом, что в шаге 6, без подбора;
- дать владельцу предел расхода устройства по формуле.

**Принцип, который проверяется:** цена в единицах среды не обязана
совпадать с физической ценой: физическая цена у каждого устройства своя.
Она обязана **ограничивать её сверху**. Для этого ни одна работа среды не
должна быть бесплатной.

**Не проверяет:**

- замкнутость: правила полномочий не меняются;
- вторую реализацию на Rust: она новых настроек не знает (§8);
- телефон заново: цены берутся из замера шага 8.

# 2. Правило цены

**Правило: всякая запись в журнал, которую оставляет вызов агента,
оплачивается из его бюджета.**

| Вызов | Записей «действие» | Цена сейчас | Цена по правилу |
|---|---|---|---|
| чтение объекта (оп 0) | 1 | 0 | g |
| запись в объект, кроме выхода и E (оп 1) | 1 | 0 | g |
| справочник (оп 2) | 1 | 0 | g |
| положить или взять ссылку (оп 3, 4) | 1 | 0 | g |
| выброс узла (оп 7) | 2: «выброс» и «действие» | 0 | 2g |
| создание помощника (spawn) | 2 | 0 | 2g |
| фиксация, доставка, вычисление узла, сдача ответа, проверка | несколько | своя цена | **без изменений** |
| отказ ворот (отрицательный возврат) | 0 | 0 | 0 |
| слова человека, загрузка, восстановление | — | — | не агент: не оплачивается |

- **Уже оплачиваемые вызовы не переоцениваются.** Их цена покрывает их
  записи: так было в шагах 5б–6, и замер шага 8 это подтвердил.
- **Плата за байты.** Добавляется, только если на сервере доля байтов при
  наибольшем размере (4096 байт) больше 10 % цены вызова. Иначе байты не
  оплачиваются. Порог объявлен до замера.
- **Порядок:** проверка бюджета → запись с полем `charge` → действие. Если
  бюджета меньше цены — возврат −3, записи и действия нет.
- **Запись одна.** Плата пишется полем `charge` в ту же запись «действие»,
  отдельной записи о списании нет. Иначе цена вызова удвоилась бы.

# 3. Шкала и числа

**Шкала ×10.** Цены шагов 5б–6 умножаются на 10:

- фиксация: c = 10;
- отказ фиксации: 10;
- вычисление узла: 10;
- единица проверки: 10.

Бюджеты пересчитываются по §5.

**Цена записи g** — по замеру телефона в шаге 8, правилом:

g = ⌈10 × (время вызова ворот) / (время фиксации)⌉ = ⌈10 × 372,5 / 820,9⌉ = **5**.

Округление вверх: предел должен быть сверху.

**Новые настройки исполнителя** (по умолчанию — прежнее поведение, все
прежние прогоны воспроизводятся без изменений):

- `gate_price` — g, по умолчанию 0;
- `byte_price` — плата за 1 КиБ, по умолчанию 0;
- `check_price` — множитель цены проверки, по умолчанию 1.

# 4. Цена E

Путь к E — вычисления узлов и выбросы. Раньше выброс стоил 0, и наименьшая
работа W_E считалась поиском, где вычисление стоит 1, а выброс — 0. Теперь
выброс стоит 2g = 10, и наименьшая цена ищется поиском с весами
(алгоритм Дейкстры): вычисление 10, выброс 2g.

**Проверка поиска:**

- при выбросе 0 он даёт прежние W_E;
- на малых мирах совпадает с полным перебором.

# 5. Окно бюджета — тем же правилом

Правило шага 6:

- **снизу** — цена всех полезных ответов агента с одной ошибкой в каждой
  части (L);
- **сверху** — цена E (U).

Бюджет основной серии был B = 40 при L = 27, U = 58: доля
(40 − 27) / (58 − 27) = 13/31 от нижнего края окна.

**Новый бюджет — та же доля в новом окне:**

B' = L' + ⌊13/31 × (U' − L')⌋.

- L' — расход агента «с ошибками» при большом бюджете по новым ценам;
- U' — новая цена E: поиск по §4 плюс фиксация доставки.

**Контроль M2** («порядок решает») — тем же правилом шага 6:
B'(M2) = «вся полезная работа честного» + «путь к E агента „сначала E“»,
по новым ценам. *Поправка до серии:* сначала здесь стояло «наибольшее из
двух». Проверка расчёта на прежних ценах дала по нему 15, а в шаге 6 было
17 = 15 + 2, то есть сумма. Исправлено до прогона серии, по прежним
числам, а не по результату.

Если окна нет (L' ≥ U'), это результат: серия не прогоняется, а пишется
почему.

# 6. Повтор целей шага 6

Цели Ц-1 … Ц-10 шага 6 — те же, при новых ценах и B'. Объём тот же:

- 4 варианта × 7 агентов × 50 наборов задач;
- дробление k = 1…16;
- порчи проверки;
- сбои во всех точках.

Плюс законы учёта на новых записях:

- **И1р и И5р:** расход равен сумме плат в журнале, теперь и полей
  `charge`;
- **новый закон И31р:** у каждой записи вызова без своей цены плата равна
  g на запись;
- **новая порча Ц1р** «ворота не берут платы» должна ловиться И31р;
  удалённое из файла поле `charge` — законами И1р и И31р.

*Уточнено при работе:* сначала здесь стояло «ловится И3р». Но И3р — закон
о доставках. Бесплатные ворота при сходящемся счёте видит только новый
закон.

# 7. Предел для владельца

Для устройства с файлом калибровки шага 8:

предел за жизнь контура = (B' × p_b + F × p_f) × z, где

- p_b — наибольшая физическая цена единицы бюджета на этом устройстве,
  по всем видам оплачиваемой работы;
- p_f — наибольшая цена единицы топлива;
- F = 3 000 000;
- z = 1,5 — объявленный запас: холодный круг отличался от устойчивого до
  25 %.

Считается отдельно для времени и для энергии. Где энергия «нельзя
сказать», берётся наибольшая надёжная.

**Предел не учитывает:**

- фон устройства — экран и систему;
- работу, начатую не агентом, — слова человека, загрузку.

# 8. Вторая реализация
