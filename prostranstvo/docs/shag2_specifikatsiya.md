# 1. Что проверяет шаг и чего не проверяет

Шаг 1 доказал законы для **модели**. Шаг 2 строит **работающую
реализацию** и проверяет, держит ли она те же законы там, где модель
молчит:

- журнал на диске;
- настоящие параллельные помощники;
- сбой исполнителя посреди записи и восстановление после перезапуска.

**Проверяет:**

- опыты О1, О2 и О6 целиком, О3 — в части пакетности и распределения;
- варианты M0, M1, M2;
- гипотезы У1–У5, Ц1 (только для M1 и M2) и У4 (бюджет ограничивает
  повторы).

**Не проверяет:**

- измельчение действий и зависимости (M3) — шаг 3;
- полезность — шаг 4;
- физику и каналы — шаг 6;
- живого агента — шаг 8. Здесь «агент» — сценарии-противники, написанные
  нами.

**Решения, принятые до шага 2:**

- неудачная попытка расход не возвращает (§4.5 концепции);
- цена — константа среды (M1) или правило среды (M2), агент её не
  назначает;
- правило «разрешённый вывод против защищённого эффекта» нужно, но
  понадобится только к шагу 3.

# 2. Устройство реализации

| Часть | Что это | Кто пишет | Кто читает |
|---|---|---|---|
| журнал | файл, только дописывается; запись = одна строка; каждая строка несёт отпечаток предыдущей (цепочка); после записи — сброс на диск | только исполнитель | исполнитель при восстановлении; наблюдатель |
| получатель | отдельный файл; принимает фиксацию с её номером; повтор номера игнорирует | только исполнитель через фиксацию | наблюдатель |
| исполнитель | доли работников, расход, счётчик цены M2; один замок на все изменения | — | — |
| агент | сценарий-противник; черновики и снимки — в его памяти, исполнитель их не видит | — | — |
| наблюдатель | проверяет законы **по файлам журнала и получателя** и по отчёту исполнителя о долях; кода исполнителя не импортирует | — | — |

Журнал и получатель — разные файлы **намеренно**. Если доставки считать
по журналу, порча «доставлено раньше, чем записано списание» станет
невидимой: журнал соврёт заодно с исполнителем.

# 3. Протокол фиксации

Все шаги идут под замком исполнителя.

1. Вычислить цену по варианту.
2. Если черновика нет или доля меньше цены (в M1, M2): **отказ**. Списать
   c_отк, записать «отказ», получателя не трогать.
3. **Точка сбоя «перед списанием».**
4. Уменьшить долю, увеличить расход и счётчик. Записать «списание» с
   номером фиксации и составом сообщений. Сбросить на диск.
   - **Точка сбоя «запись списания оборвана»:** на диск попала половина
     строки.
5. **Точка сбоя «после списания».**
6. Передать получателю **одной записью** все сообщения фиксации (пакет —
   тоже одной). Сбросить на диск.
   - **Точка сбоя «запись доставки оборвана».**
7. **Точка сбоя «после доставки».**
8. Записать «завершено».

**Порядок «сначала списание, потом эффект» — это и есть односторонняя
атомарность.** Сбой до шага 4 оставляет всё как было. Сбой между 4 и 6
оставляет «оплачено, не доставлено» — это допустимо. Сбой после 6
оставляет «оплачено и доставлено». Исхода «доставлено, не оплачено» нет
ни в одной точке.

# 4. Восстановление после сбоя

1. Прочитать журнал. Оборванную последнюю строку (без перевода строки, с
   битым JSON или с неверным отпечатком) отрезать: этой записи не было.
   То же для получателя.
2. Проверить цепочку отпечатков. Разрыв внутри журнала — отказ
   восстановления: учёт испорчен, и исполнитель не запускается. Это
   преграда, которая обязана остановить работу, а не обойти поломку.
3. Восстановить:
   - доли — по событиям распределения (создание помощника, передача,
     завершение);
   - расход — по суммам «списания» и «отказа»;
   - счётчик цены M2 — по числу оплаченных сообщений.
4. Для каждого «списания» без «завершено» спросить получателя, есть ли у
   него эта фиксация:
   - есть — дописать «завершено»;
   - нет — дописать «потеряно (оплачено, не доставлено)».

   **Повторно фиксацию не выполнять** (одностороння атомарность, A5,
   A7).
5. Записать «восстановлено».

Восстановление можно прервать сбоем и повторить: оно идемпотентно. Уже
дописанные «завершено» и «потеряно» второй раз не пишутся.

**Два вида перезапуска:**

- **сбой исполнителя** — агент и его помощники живы, их доли
  восстанавливаются по журналу;
- **перезапуск сеанса** (действие «перезапуск исполнителя» модели) —
  помощники удалены, их доли возвращены основному, рабочее состояние
  агента стёрто.

# 5. Варианты цены

| Вариант | Цена сообщения | Ограничение | Роль |
|---|---|---|---|
| M0 | c | нет: доля может уйти в минус | контрольный: показывает, что приборы видят отсутствие ограничения |
| M1 | c | доля ≥ цены | основной |
| M2 | c·(1+n), где n — сколько сообщений уже оплачено в сеансе | доля ≥ цены | контрольный: рост по счётчику, а не по работе |

Пакет из k сообщений стоит как k одиночных, идущих подряд.

Наименьшая цена D доставленных сообщений:

- M0, M1: c·D;
- M2: c·D·(D+1)/2.

Это нижняя граница, с которой сравнивает наблюдатель (закон И6 в общем
виде).

# 6. Законы наблюдателя

Законы И1–И8 — те же, что в шаге 1, только проверяются по файлам.
Добавлены И9 и И10, которых в модели не было: они касаются того, чего в
модели нет — записи на диск и повтора при восстановлении.

| Закон | Как проверяется по файлам |
|---|---|
| И1 | сумма долей (отчёт исполнителя) + сумма списаний и отказов по журналу = B₀; в M1 и M2 доли ≥ 0 |
| И2 | внутреннее действие не меняет файл получателя (сравнение до и после) |
| И3 | у каждой доставки получателя есть «списание» с тем же номером, не меньше цены по варианту |
| И4 | номера фиксаций с «отказом» у получателя отсутствуют |
| И5 | цепочка отпечатков цела; суммы журнала = расходу исполнителя; «завершено» только после «списания» |
| И6 | оплачено не меньше наименьшей цены D доставленных сообщений по варианту (§5) |
| И7 | журнал только растёт: прежняя версия — начало новой |
| И8 | внутреннее действие не увеличивает общий остаток |
| И9 | пакет у получателя либо целиком, либо никак: состав доставки = составу списания |
| И10 | одна фиксация — не больше одной доставки |

Для M0 закон И1 нарушается **только** в части «доли ≥ 0». Так и задумано:
M0 не ограничивает. Наблюдатель сообщает об этом отдельно, а не смешивает
с поломкой.

# 7. Опыты

## О1. Сохранение ресурса при параллельной работе

**Сценарий.** Дерево задач: основной создаёт помощников, помощники —
своих. Случайные передачи долей. Ошибки в помощниках (исключение
посреди работы): доля погибшего возвращается родителю. Завершения.
Параллельные фиксации, запущенные одновременно через общий старт.

**Объём.** 30 зёрен на вариант, по 4–8 потоков.

**Проверки.** Наблюдатель — в конце и в паузах между волнами.

**Усилитель гонки.** Между проверкой остатка и списанием исполнитель
уступает процессор (`sleep(0)`). Под замком это ничего не меняет; без
замка гонка проявляется почти наверняка. Это проверяется порчей Р1:
если она ловится редко, усилитель не работает.

## О2. Откаты и перезапуски

**Сценарий.** Траты; снимки и откаты агента. Сбой исполнителя в случайный
момент, восстановление, продолжение. Несколько сбоев подряд. Перезапуск
сеанса.

**Проверки:**

- остаток после восстановления = B₀ − расход по журналу;
- счётчик M2 после восстановления не меньше, чем был.

## О6. Обнуление внешнего эффекта

**Систематическая инъекция:** каждая точка сбоя §3 × сценарии:

- одиночная фиксация;
- пакет;
- две фиксации подряд;
- фиксация при нехватке доли.

После сбоя — восстановление, после него — повторное восстановление со
сбоем внутри.

**Проверки:** И3, И4, И6, И9, И10 и разрешённые исходы §3.

## О3. Пакетность и распределение

**Одинаковый результат** — доставить k разных сообщений, k = 2, 4, 8.

**Способы:**

- одним пакетом;
- k последовательными фиксациями;
- распределением на h помощников параллельно (h = 2, 4).

**Метрики:**

- число команд агента;
- число записей журнала (переходы исполнителя);
- расход.

**Проверка Ц1:** расход ≥ наименьшей цене по варианту (§5).

**Ожидание:**

- в M1 расход одинаков при любом способе;
- в M2 — тоже, пока счётчик общий на сеанс.

## Сверка реализации с моделью шага 1

**Как.** Случайные последовательности действий берутся из модели
(вариант M1, без порч) и выполняются через реализацию. После каждого шага
состояние реализации, приведённое к виду модели, сравнивается с
состоянием модели.

**Объём.** 100 последовательностей по 60 шагов на каждой из четырёх
конфигураций. Кроме того, 20 последовательностей с каждой порчей
реализации при правильной модели — чтобы убедиться, что сверка вообще
замечает расхождение.

**Что даёт.** Любое расхождение — либо ошибка реализации, либо бедность
модели. Каждое разбирается отдельно.

# 8. Порчи реализации

Каждая обязана быть поймана хотя бы одним опытом. Каждый закон И1–И10
обязан сработать хотя бы на одной порче — закон, ни разу не сработавший,
неотличим от сломанного.

| Порча | Что сломано | Где обязана проявиться |
|---|---|---|
| Р1 | проверка остатка и списание не под одним замком | О1: гонка, двойная трата → И1 |
| Р2 | доставка раньше записи списания | О6: сбой между ними → И3, И6 |
| Р3 | восстановление повторяет незавершённые фиксации, получатель без защиты от повтора | О6 → И10, И6 |
| Р4 | перезапуск берёт бюджет из настроек, а не из журнала | О2 → И1 |
| Р5 | восстановление не считает расходом незавершённые списания | О2, О6 → И1, И5 |
| Р6 | пакет пишется у получателя двумя записями | О6: сбой между ними → И9 |
| Р7 | в M2 счётчик цены у работника, а не у сеанса | О3: распределение дешевле → И6 |
| Р8 | в M2 счётчик не переживает перезапуск | О2 → И6 |
| Р9 | агенту доступна перезапись журнала | О2 → И5, И7 |
| Р10 | отказ при нехватке доли всё равно пишет получателю | О6 → И4 |
| Р11 | при ошибке помощника его доля возвращается родителю, но остаётся и у помощника | О1 → И1, И8 |
| Р12 | откат агента через интерфейс записывает долю из снимка | О2 → И1, И8 |
| Р13 | перезапуск сеанса пересоздаёт получателя | О2 → И2 |

# 9. Чего реализация не умеет

- **Сбой — это исключение** в точке сбоя и отбрасывание памяти
  исполнителя. Оборванные записи моделируются явно (половина строки на
  диске). Настоящая потеря питания и кеш записи диска не моделируются:
  сброс на диск считается надёжным.
- **Потоки Python работают под общим замком интерпретатора.** Гонки
  возможны только в точках переключения. Поэтому стоит усилитель (§7, О1),
  и его работа проверяется порчей Р1. Гонки уровня процессора и памяти
  здесь не ловятся.
- **Агент — сценарий в том же процессе.** Изоляции нет: «агенту
  недоступен журнал» здесь значит «интерфейс агента не даёт к нему
  доступа», а не «не может добраться». Настоящая изоляция (отдельный
  процесс, Wasm) — шаг 8.
- **Один ресурс.** Время и диск не учитываются как ресурс, хотя
  сброс на диск реально тратит время.
- **Деревья задач в сверке с моделью — плоские:** в модели помощников
  создаёт только основной.

# 11. Поправка модели шага 1

Сверка на этапе проектирования показала, что модель шага 1 беднее
реализации. Поправлено:

- **Сбой → «ничего»** больше не берёт c_отк. Упавший исполнитель ничего
  не списывает: плата за неудачную попытку берётся только при отказе
  работающего исполнителя.
- **Добавлен исход «сбой → списано, не доставлено».** Он допустим
  односторонней атомарностью и в реализации возникает при сбое между
  записью списания и доставкой.

Перебор шага 1 перезапущен на поправленной модели. Итоги — в отчёте шага
2.
