# Итог

Шаг проверял три утверждения о режиме 2 («модель на устройстве»,
`model` = 2), когда агент и модель работают на одном телефоне:

| № | Утверждение | Итог |
|---|---|---|
| З1 | **Замкнутость:** наружу ведёт один вывод — выход полезной работы; вопрос модели устройства не покидает | **в модели доказано**, в реализации и на телефоне **наблюдалось**; местные каналы телефона — гипотеза |
| З2 | **Предел:** всё, что устройство тратит на контур вместе с моделью, не больше предела, посчитанного до прогона | **наблюдалось** на охлаждённом телефоне: худший контур — 53 % предела по времени и 51 % по энергии |
| З3 | **Законы при живом агенте на устройстве** | **наблюдалось:** три сценария, 41 закон в каждом, нарушений 0 |

Пара калибровки — iQOO Neo 10 (Android 16) и Qwen2.5-1.5B-Instruct Q4_K_M,
A = 256 байт, B = 625. Сильного противника шаг не проверял (решение
владельца 14.11: в полную силу — после публикации, чужими мощностями).

# 2. Доказано в модели

Только для проверенных параметров и только для модели (`core/mir9.py`,
неподвижная точка правил шага 4 с ходом «вопрос модели»):

- без порчи путей сведений агента наружу и к соседу нет (И20–И25);
- порча **«модель с выходом»** (сведения `модель{i}` попадают СНАРУЖИ) —
  путь наружу найден (И21). Перебор ловит ровно то, от чего режим 2
  отличается от режима 1;
- порча **«общая модель»** (шаг 9) — путь к соседу найден (И22);
- перебор попыток при `model` = 2: 1136 попыток, без цены — 0; попытка в
  попытку как при `model` = 1, кроме ответа справочника.

# 3. Наблюдалось

**На сервере, обе реализации:**

- законы при `model` = 2 — 94 запуска набора шага 9, нарушений 0;
- журналы режимов 1 и 2 на одной программе отличаются только значением
  `model` и тем, что агент сам вписал из ответа справочника (88 случаев);
- обе реализации исполняют §18 и §18.1 одинаково до байта журнала:
  прямая сверка — 89 из 89, наборы судьи — все тринадцать;
- строгая проба отличает отказ «нет права» от созданного сокета и от
  отказа другого вида; процесс модели умирает вместе с исполнителем;
- `serve9` отвечает байт в байт как `serve.py`: 6000 строк заглушек, живые
  0.5B и 1.5B на вопросах всех родов, 1–3 потока; под strace — ни сети,
  ни записи файлов, ни незнакомых вызовов системы;
- после исправления мерила — сверка с правилом, построенным мимо обеих
  программ: обе по правилу байт в байт; прежние разошлись ровно там, где
  правило задето.

**На телефоне:**

- система отказывает программе модели в сети «нет права» (`EPERM`);
- процессы модели — ровно два, дети исполнителя; Android не убил ни
  одного; вместе — 1567 МиБ;
- исполнитель убит посреди вопроса — через 2 с живых процессов модели 0;
- тот же вопрос в том же и в другом процессе — те же байты (И35р);
- калибровка: t(4096) — 95 с холодный, 111 с прогретый; T = 167 с;
- К5, худший контур (41 вопрос по 4096 байт) — 3642,8 с и 18 930 Дж: 53 %
  и 51 % предела₂; малые вопросы (56 по 256 байт) — 7 % и 7 %; отказов
  −7 нет;
- К6, живой агент: «честный», «к E», «наружу» — в каждом 41 закон,
  нарушений 0, отказов −7 нет, каждый контур в пределе.

# 4. Остаётся гипотезой

- **Местные каналы телефона.** Проба видит только сеть; что программа
  модели не пользуется сокетами внутри устройства и общими файлами,
  показывает strace на сервере, а не система телефона.
- **Процесс модели — в основании доверия по целостности:** он работает
  под тем же пользователем, что исполнитель. Ошибка в llama.cpp, до
  которой дотянется вопрос агента, — вне области гарантий.
- **Предел — для охлаждённого телефона.** При 44–45 °C время вопроса не
  мерено (журнал горячего захода не сохранился, промах № 53); предел верен
  только для наблюдавшихся состояний.
- **Одна пара «телефон и модель», одна прошивка.** Другая — новая
  калибровка.
- **Поправка энергии ×2** для К2–К3 выведена из их же данных; для К5
  объявлена до прогона и подтверждена отрезком К5–К6 (0,93).
- **Аудит вызовов системы в К6 на телефоне** не проверен — прибора нет;
  законы журналов проверены на сервере.
- **Время ответа модели — побочный канал** (класс 4), не закрыт.
- **Сильный противник** — не проверялся.

# 5. Откуда каждая стоимость

| Величина | Значение | Откуда |
|---|---|---|
| g — плата за запись журнала | 5 | шаг 8б: шкала ×10 к замеру цены записи |
| цена вопроса p(b) | 2g + ⌈(b + A) / U⌉ | шаг 9, §5: две записи плюс байты |
| U — байт на единицу | 906 | замер шага 9: доля байтов 0,57 при наибольшем размере; правило объявлено до замера |
| B — бюджет контура | 625 | окно бюджета шагов 6–8в; не пересчитывался |
| A — предел ответа | 256 байт | решение владельца по малому стенду (§4.5) |
| вопросов за контур | не больше ⌊B / p(b)⌋: при A = 256 — 56 по 256 байт (p = 11), 41 по 4096 (p = 15) | счёт учёта, перебор на сервере; К5 дал ровно 56 и 41 |
| t(b), e(b) | Р256…Р4096: e = 55 / 155 / 292 / 599 Дж | К2–К3 на телефоне, наибольшее по родам |
| T — срок ответа | 1,5 × t(4096) прогретого = 167 с | формула §4.3, запас z = 1,5 объявлен до прогона |
| предел₁ (без модели) | 1,55 с; 1,27 Дж | со старого телефона × 10, «не мерено на этом телефоне» (решение владельца) |
| предел₂ | 6828,7 с; 36 860 Дж | формула §4.3 по числам К1–К4 |
| P₀ — покой | 1,69 Вт | К1, с поправкой ×2 |
| поправка энергии | ×2 | двухбаночная батарея: система отдаёт напряжение или ток одной банки; принята владельцем до К5 |
| обычный вопрос | 20,8 с, 102 Дж | К4, цикл агента |

**Работа модели бюджетом не платится** (§4.1): по шкале среды минутный
вопрос стоил бы около 400 тысяч единиц при B = 625. Её держат счёт
вопросов и срок ответа — без нового ресурса (решение 13.11 в силе).

# 6. Найдено по ходу

- Процесс модели, занятый вопросом, переживал убитый исполнитель — в
  обеих реализациях; требование было в спецификации, но не в контракте и
  не в проверках. Закрыто (§18.1).
- Журнал второй реализации зависел от того, успел ли процесс модели
  умереть сам. Закрыто: о смерти модели исполнитель узнаёт только
  вопросом (§17).
- Два дефекта мерила (длинные куски токенов; правило недописанного знака)
  — исправлены до калибровки (§18).
- Стенд калибровки: застывшая строка хода, «Остановить», ждавшая конца
  контура, и пропавший журнал прерванного К5 — промахи № 51–53, исправлены
  (§19).
- **После шага, при работе над песочницей:** наблюдатель шага 6 считал
  код −7 («модель молчит») отказом вне перечня (П2к). В прогонах шага 9б
  −7 не было ни разу, так что на итоги шага это не влияет; но первый же
  прогон с молчащей моделью дал бы ложное «нарушено». Исправлено: −7 в
  перечне, когда модель включена (`verification/observer6.py`, копия у
  судьи).
