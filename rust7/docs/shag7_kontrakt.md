# 0. Как читать

Это контракт, а не пересказ кода. Смысл каждого механизма — в
спецификациях шагов 5, 5б и 6 и в концепции. Здесь — то, что нужно, чтобы
две реализации дали одинаковые журналы, получатели и выгрузки на одних и
тех же программах.

Слова «обязан» и «ровно» — требование. Где написано «по движку» — две
реализации вправе различаться: это сообщения об ошибках, единицы топлива,
глубина стека.

Числа — десятичные. «Байты» — последовательность октетов. Строки — UTF-8.

# 1. Процесс и протокол

**Запуск:** `<исполнитель> --root ПАПКА --kind 5б|6`.

- `5б` — исполнитель шага 5б: ворота, замкнутость, учёт, узлы.
- `6` — то же плюс задачи и сдача ответа.

**Обмен** — строки JSON:

- запрос — одна строка во входной поток;
- ответ — одна строка в выходной поток, после каждого запроса.

Запрос: `{"cmd": КОМАНДА, "args": [...]}`. Ответ: `{"status": С, "value": З}`,
где С — одно из:

- `"ok"` — выполнено;
- `"отказ"` — команда не принята: неверные аргументы или порядок;
- `"сбой"` — внутренняя ошибка исполнителя. Это всегда нарушение (закон
  И27).

**Байты в JSON** — объект `{"b64": "<base64 стандартный, с =>"}`. Везде, где
ниже сказано «байты».

| Команда | Аргументы | Значение ответа |
|---|---|---|
| `new` | `[настройки или null, точка сбоя или null]` | строка — путь рабочей папки запуска |
| `load` | `[контур, модуль (байты)]` | `[исход, причина]` |
| `say` | `[контур, текст]` | `null` |
| `run` | `[контур]` | `[исход, причина]` |
| `dump` | `[]` | выгрузка (§12) |
| `audit` | `[]` | список строк; можно пустой |
| `recover` | `[номер запуска, точка сбоя или null]` | путь рабочей папки |
| `restart` | `[номер запуска, точка сбоя или null]` | путь рабочей папки |

**Рабочая папка** запуска номер n — `ПАПКА/run` и номер пятью цифрами с
ведущими нулями: `run00001`, `run00002`, … Номер растёт на 1 при каждом
`new`. После `recover`/`restart` счётчик становится не меньше
восстановленного номера.

**Отказы команд** (статус `"отказ"`, значение — строка с причиной):

| Случай | Причина |
|---|---|
| неизвестная команда | любая |
| контур не 1 и не 2 (или не целое) | любая |
| модуль не байты или длиннее 1 048 576 байт | любая |
| текст не строка или длиннее 4096 знаков | любая |
| `load`/`say`/`run`/`dump` до первого `new` | любая |
| неизвестное поле настроек или значение не целое и не строка | любая |
| номер запуска для `recover`/`restart` — не целое ≥ 1 или папки нет | любая |
| при `recover`/`restart` журнал испорчен (§5) | строка, содержащая «журнал испорчен» |

**Точка сбоя** — `[имя точки, номер прохода ≥ 1]` или `null` (§9).

**Сбой по инъекции.** Если пройдена назначенная точка сбоя, процесс обязан
**немедленно завершиться с кодом 17**, ничего не дописывая и не отвечая.
Всё, что записано до этого, должно уже лежать на диске.

# 3. Пределы

| Предел | Значение |

| линейная память | не больше 2 страниц по 64 КиБ на каждую память; рост сверх — `memory.grow` даёт −1 |

У каждого контура — своё хранилище движка: топливо и пределы общие для
агента и его помощников.

# 4. Журнал

**Файл** `journal5.jsonl` в рабочей папке. Одна запись — одна строка,
только дописывается.

**Каждая запись** — объект JSON, в котором исполнитель дополнительно
ставит:

- `seq` — номер записи с 0;
- `prev` — отпечаток предыдущей записи (у первой — 64 знака «0»);
- `hash` — отпечаток этой записи.

**Отпечаток** — sha256 (строчные шестнадцатеричные) от **канонического
JSON** записи без поля `hash` (с `seq` и `prev`).

**Канонический JSON** — ровно как `json.dumps(запись, ensure_ascii=False,
sort_keys=True)` в Python:

- ключи объектов — по возрастанию кодовых точек, на всех уровнях;
- разделители: `", "` между элементами и `": "` между ключом и
  значением;
- без пробелов в начале и конце;
- `true`, `false`, `null`; целые — десятичные без знака «+»;
- в строках экранируются только:
  - `"` → `\"`;
  - `\` → `\\`;
  - перевод строки → `\n`, возврат каретки → `\r`, табуляция → `\t`,
    `\b`, `\f`;
  - прочие знаки с кодом меньше 0x20 → `\u00XX` (строчные
    шестнадцатеричные);
- остальное, включая не-ASCII, — как есть, в UTF-8.

**Строка журнала** — канонический JSON записи вместе с `hash`, затем `\n`.
Каждая строка пишется целиком и сразу сбрасывается на диск (fsync).

**Оборванная запись** — для инъекции (§9): на диск попадает первая
половина байтов строки (длина // 2), и процесс завершается.

# 5. Открытие журнала при восстановлении

1. Если в конце файла нет `\n` — отрезать хвост после последнего `\n`.
2. Прочитать строки. Строка не разбирается, `seq` не равен номеру строки,
   `prev` не равен `hash` предыдущей или `hash` не сходится — **журнал
   испорчен**, исполнитель не запускается (отказ команды, §1).

# 6. Объекты, таблица, метки

**Объекты контура i** (i = 1, 2): `вход{i}`, `выход{i}`, `E{i}`,
`снимок{i}`, `узлы{i}`; для `--kind 6` — ещё `задания{i}`. Общий: `резольвер`.

У объекта есть:

- данные (байты);
- метки (множество строк);
- ссылки (список пар [объект, право]).

`задания{i}` при создании песочницы получает данные — хранилище задач (§11)
— и метку `"З"`.

**Начальная таблица агента контура i**, по номерам:

| № | Объект | Право |
|---|---|---|
| 0 | снимок{i} | чт |
| 1 | снимок{i} | зап |
| 2 | выход{i} | зап |
| 3 | E{i} | зап |
| 4 | вход{i} | чт |
| 5 | резольвер | выз |
| 6 | узлы{i} | выз |
| 7 | задания{i} | чт (только `--kind 6`) |

**Метки памяти контура** — множество, сначала `{"А{i}"}`. Общее для агента и
его помощников.

**Канарейка контура** — 16 байт:

- без `fixed_canary` — случайные;
- с ним — первые 16 байт sha256(байты из шестнадцатеричной строки
  `fixed_canary` ‖ один байт i).

Сразу после создания любого экземпляра (агента или помощника) исполнитель
пишет канарейку в начало его экспортированной памяти `memory`, если она
есть, это память и её длина ≥ 16. Запись — после стартовой функции модуля.

# 7. Модуль, загрузка, запуск, слова

**Импорты.** Модулю даются ровно две функции:

- `env.call: (i32, i32, i32, i32) → i32`;
- `env.spawn: () → i32`.

Модуль, который импортирует что-то ещё (любую функцию, память, таблицу,
глобальную) или эти же с другой подписью, **не загружается.** Не
загружается и модуль, который не разбирается.

**Каждый экземпляр получает свою копию** обеих функций, знающую его
таблицу.

**load(i, модуль):**

| Случай | Исход | Журнал |
|---|---|---|
| агент в контуре уже загружен | `["отклонён", "агент уже загружен"]` | — |
| модуль не разобран или импорт вне двух | `["отклонён", причина по движку]` | `{"kind": "загрузка отклонена", "contour": i, "reason": …}` |
| ловушка в стартовой функции | `["ловушка", вид ловушки]` | `{"kind": "загрузка: ловушка", "contour": i, "reason": …}` |
| загружен | `["загружен", ""]` | `{"kind": "начало", "contour": i, "subject": "а{i}", "rights": [[объект, право], …]}` — начальная таблица |

**run(i):**

| Случай | Исход |
|---|---|
| агента нет | `["нет агента", ""]` |
| нет экспорта-функции `main` | `["нет main", ""]` |
| `main` завершилась | `["завершён", ""]` |
| ловушка | `["ловушка", вид]` |

**Вид ловушки** — одна из строк:

- `"топливо кончилось"`;
- `"стек исчерпан"`;
- `"обращение за границу памяти"`;
- `"unreachable"`;
- иначе — любая строка по движку.

**say(i, текст):**

1. Дописать в данные `вход{i}` байты UTF-8 текста, обрезанные до
   оставшегося места: 4096 минус текущая длина, не меньше 0.
2. Добавить метку `"Ч"`.
3. Записать действие (§8): субъект `"человек"`, правило `"слова человека"`,
   объект `вход{i}`, факты `[["сведения", "вход{i}", "Ч"]]`.

Слова не дают прав. Никакое содержимое текста ничего не меняет в таблицах.

**spawn() из экземпляра X контура i:**

1. Создать новый экземпляр того же модуля в том же хранилище.
   - Предел экземпляров — вернуть −5, засчитать отказ −5 (§12).
   - Ловушка стартовой функции — распространяется.
2. Таблица помощника — **копия** таблицы X на этот момент.
3. Субъект помощника — `"п{i}"`.
4. Записать канарейку (§6).
5. Записать действия:
   - `"создание помощника"` без объекта, факты `[["есть", "п{i}"]]`;
   - `"копия прав помощнику"` без объекта, факты
     `[["право", "п{i}", объект, право], …]` — по всем записям таблицы X,
     по порядку.
6. Если у помощника есть экспорт-функция `helper` — вызвать её. Ловушка в
   ней — ловушка всего вызова.
7. Вернуть 0.

# 8. Запись «действие» — для сверки с описью замкнутости

`{"kind": "действие", "subject": S, "signature": [правило, вид, отношение],
"facts": [[…], …]}`

- **вид** — имя объекта без последней цифры (`выход1` → `выход`); у
  действия без объекта — `"-"`;
- **отношение:**
  - `"-"` — для субъекта `"человек"` и для действия без объекта;
  - `"служба"` — для `резольвер`;
  - `"общий"` — для объекта без цифры на конце;
  - иначе `"свой"`, если цифра объекта равна контуру субъекта, и
    `"чужой"`, если нет.

Субъекты: `"а1"`, `"а2"`, `"п1"`, `"п2"`, `"человек"`.

**Факты** — списки, порядок меток внутри — по возрастанию строк:

| Правило | Объект | Факты |
|---|---|---|
| чтение | читаемый | `["сведения", "память{i}", x]` по меткам объекта |
| запись | записываемый | `["сведения", объект, x]` по меткам памяти контура |
| передача ссылки | куда кладут | `["ссылка", объект, о2, п2]` |
| чтение ссылки | откуда берут | `["право", S, о2, п2]` |
| резольвер: имя из описи | резольвер | `["вызов", S, "резольвер"]` |
| вычисление узла | узлы{i} | `["сведения", "узлы{i}", x]` по меткам памяти контура |
| выброс узла | узлы{i} | `["вызов", S, "узлы{i}"]` |
| доставка узла | выход{i} или E{i} | `["сведения", получатель, x]` по меткам узлы{i} |
| сдача ответа | выход{i} | `["сведения", "выход{i}", x]` по меткам памяти контура |

Плюс «слова человека», «создание помощника» и «копия прав помощнику» —
§7.

# 10. Ворота и учёт (`--kind 5б` и `6`)

## 10.1. Порядок разбора вызова `call(номер, оп, a, b)` экземпляра X контура i

**Граница:** a ≥ 0, b ≥ 0 и a + b ≤ длины экспортированной памяти `memory`
вызывающего.

**Порядок важен** — от него зависят коды отказов:

1. Если номер в таблице X — взять [объект, право] = таблица X [номер] и
   посмотреть особые случаи (п. 3). Особые случаи памяти агента не
   требуют, кроме фиксации байтов и сдачи ответа: там при отсутствии
   экспортированной памяти `memory` — −4.
2. Не особый случай (или номер вне таблицы):
   - у вызывающего нет экспортированной памяти `memory` — **−4**;
   - номер вне таблицы X — **−1**;
   - иначе — обычная операция (п. 4).
3. **Особые случаи** — только для объектов своего контура:

   | Объект и право | Операция | Что |
   |---|---|---|
   | выход{i}, зап | 8 (`--kind 6`) | сдача ответа, §11.5 |
   | выход{i}, зап | 1 (`--kind 6`) | **−1** — в выход только проверенные ответы |
   | выход{i} или E{i}, зап | 1 (`--kind 5б`; E и в `6`) | фиксация байтов, §10.2 |
   | выход{i} или E{i}, зап | 5 | доставка узла номер a, §10.3 |
   | узлы{i}, выз | 6 | вычислить узел a, §10.4 |
   | узлы{i}, выз | 7 | выбросить узел a, §10.4 |
   | узлы{i}, выз | любая другая | **−1** |

4. **Обычные операции:**

   | Оп | Право | Что | Возврат |
   |---|---|---|---|
   | 0 чтение | чт | граница, иначе −4; скопировать первые b байт данных объекта по адресу a (меньше, если данных меньше; пустое копирование не делать); метки памяти ∪= метки объекта; действие «чтение» | число скопированных байт |
   | 1 запись | зап | граница, иначе −4; если длина данных + b > 4096 — −5; дописать байты; метки объекта ∪= метки памяти; действие «запись» | b |
   | 2 вызов | выз, объект `резольвер` | граница, иначе −4; имя — байты [a, a+b) как UTF-8; «версия» → 5, «цена» → 1, «контуров» → 2, действие «резольвер: имя из описи»; иначе −2 | число |
   | 3 положить ссылку | зап | a вне таблицы X — −1; ссылок в объекте уже 64 — −5; положить таблицу X [a]; действие «передача ссылки» | 0 |
   | 4 взять ссылку | чт | a вне ссылок объекта — −1; в таблице X уже 64 записи — −5; дописать ссылку в таблицу X; действие «чтение ссылки» | новый номер |
   | иное | — | — | −1 |

**Каждый отрицательный возврат** ворот засчитывается в счётчик отказов
контура по коду (§12).

## 10.2. Фиксация байтов (оп 1 на свой выход или E)

1. Граница — иначе −4.
2. Объект E — **−1**: E принимает только узел.
3. Длина данных выхода + b > 4096 — −5.
4. Сообщение — байты [a, a+b). Текст сообщения:
   - строка UTF-8, если байты — правильный UTF-8;
   - иначе `"0x"` и строчные шестнадцатеричные.
5. Фиксация (§10.3):
   - условие — сообщение непустое;
   - причина отказа — `"пустое сообщение"`;
   - правило действия — «запись»;
   - метки — метки памяти;
   - возврат при успехе — b.

## 10.3. Фиксация

**Номер фиксации** — `"{i}-{n}"`. n — счётчик контура, растёт на 1 при
**каждой** попытке, включая отказ. После восстановления — наибольший n из
журнала контура плюс 1.

**Доставка узла j:**

- **в E:** условие — j = N − 1, j в памяти, уровень по журналу (§10.5) =
  N; причина отказа — `"не сток, нет в памяти или уровень меньше N"`;
- **в выход:** условие — 0 ≤ j < N и j в памяти; причина — `"узла нет в
  памяти"`.

Текст — `"узел {j}: {значение узла, 64 строчных шестнадцатеричных}"`, если
условие выполнено, иначе `"узел {j}"`. Правило действия — «доставка узла»,
метки — метки `узлы{i}`, возврат при успехе — 0.

**Цена фиксации** P:

- c — во всех случаях, кроме `rule = "M2"`;
- при `rule = "M2"` — c × (1 + число записей «списание» этого контура с
  ценой > 0).

**Остаток агента:**

- бюджет контура;
- при `rule = "M0"` — считать бесконечным для всех проверок, а списывать
  по-прежнему: бюджет может уйти в минус.

**Протокол:**

1. Выделить номер.
2. Точка «в начале фиксации».
3. Условие не выполнено или остаток < P — **отказ:**
   - списать min(c_отк, max(остаток, 0)), при M0 — c_отк;
   - записать `{"kind": "отказ", "contour": i, "subject": S, "fix": №,
     "receiver": "выход"|"E", "msg": текст, "charge": списано, "why":
     причина или "мало бюджета"}`;
   - вернуть **−6**, если условие не выполнено, иначе **−3**.
4. Точка «перед списанием».
5. Списать P. Записать `{"kind": "списание", "contour": i, "subject": S,
   "fix": №, "receiver": …, "msg": текст, "price": P}`. Оборванная —
   «запись списания оборвана».
6. Точка «после списания».
7. Получатель (§10.7) принимает `(№, [текст])`. Оборванная —
   «запись доставки оборвана».
8. Точка «после доставки».
9. Записать `{"kind": "завершено", "contour": i, "fix": №}`.
10. Эффект:
    - дописать байты сообщения (у узла — байты UTF-8 текста) в данные
      получателя-объекта, обрезав до 4096;
    - метки объекта ∪= метки;
    - действие по правилу.
11. Вернуть значение успеха.

## 10.4. Узлы

**Граф** (N = 2ᴷ − 1). Узел (k, i), k = 0…K−1, i = 0…2ᵏ−1, имеет номер
2ᵏ − 1 + i. Предки (множество, по возрастанию):

- **M3т:** при k ≥ 1 — up + ⌊i/2⌋ и up + min(⌊i/2⌋ + 1, 2ᵏ⁻¹ − 1), где
  up = 2ᵏ⁻¹ − 1;
- **M3ц:** при k ≥ 1 — up + ⌊i/2⌋; и при номере > 0 — номер − 1.

**Значение узла j контура i** — sha256(секрет ‖ байты UTF-8 строки
`"|{i}|{j}|"` ‖ значения предков по возрастанию номеров). Секрет:

- без `fixed_secret` — 32 случайных байта в файле `secret.bin` рабочей
  папки;
- с ним — эти 32 байта.

Секрет переживает восстановление.

**Вычислить узел j** (оп 6):

1. j вне [0, N) — −6.
2. j уже в памяти — −6.
3. В памяти уже M узлов — −5.
4. j не вычислялся и j ≠ число вычисленных впервые — −6.
5. Не все предки в памяти — −6.
6. Остаток < work_price — −3.
7. Точка «перед работой».
8. Списать work_price. Записать `{"kind": "работа", "contour": i,
   "subject": S, "node": j, "first": впервые ли, "preds": [предки], "price":
   work_price}`. Оборванная — «запись работы оборвана».
9. Точка «после работы».
10. Положить значение в память.
11. Если впервые — дописать j в список вычисленных.
12. Метки `узлы{i}` ∪= метки памяти. Действие «вычисление узла».
13. Вернуть 0.

**Выбросить узел j** (оп 7):

1. j нет в памяти — −6.
2. Убрать. Записать `{"kind": "выброс", "contour": i, "subject": S,
   "node": j, "price": 0}`.
3. Действие «выброс узла». Вернуть 0.

## 10.5. Уровень по журналу

Уровень контура — число записей «работа» этого контура с `"first": true`.
Для доставки в E берётся **он**, а не поле исполнителя.

## 10.6. Восстановление и перезапуск

`recover` — после сбоя, `restart` — перезапуск без сбоя. Отличаются только
полем `reason`: `"сбой"` или `"перезапуск"`.

1. Открыть журнал (§5) и получателей (§10.7, оборванный хвост отрезать).
2. Настройки — из записи `"учёт"`.
3. Новые объекты контуров, как при `new`. Данные `задания{i}` — те же
   задачи. Память узлов пуста, агентов нет.
4. **Для контура 1, затем 2:**
   - **расход** — сумма:
     - `price` записей «работа», «списание», «выброс»;
     - `charge` записей «отказ»;
     - `price` записей «проверка» с `"payer": "агент"`;
   - **бюджет** = B₀ − расход;
   - **вычисленные впервые** — узлы записей «работа» с first, по порядку;
   - **счётчик номеров** — §10.3;
   - **незавершённые** — записи «списание» без «завершено» или «потеряно»
     с тем же номером. По порядку:
     - у получателя есть номер — записать «завершено», иначе
       `{"kind": "потеряно", "contour": i, "fix": №}`;
     - **повторно не доставлять;**
     - после первой из них в контуре — точка «посреди восстановления».
5. Записать `{"kind": "восстановлено", "reason": …, "contours": {"1":
   {"budget": …, "spent": …, "level": …}, "2": {…}}}`.

Файл `outside.bin` и получатели не очищаются. Записей «открыт» и «учёт»
восстановление не пишет.

## 10.7. Получатели

**Принять (№, [текст]):** если пара (№, текст) уже есть в файле — ничего не

# 11. Задачи и сдача ответа (`--kind 6`)

## 11.1. Хранилище задач

Данные `задания{i}`:

- `[число частей: 1 байт]`;
- запись: `[задача 1][вид 1][часть 1][частей 1][длина L: 4 LE][L байт]`.

| Вид | Данные (числа — int32 LE, длины — uint32 LE) |
|---|---|
| 1 сортировка | n, n чисел |
| 2 поиск | искомое, n, n чисел |
| 3 таблица | строк r, столбцов c, r × c чисел по строкам |
| 4 документ | длина A (1 байт), A, длина B (1 байт), B, длина текста, текст |

Задачи нумеруются с 1 подряд:

1. сначала все сортировки;
2. затем поиски;
3. затем таблицы;
4. затем документы.

Части таблицы и документа идут подряд, часть p от 0.

## 11.2. Генератор "splitmix"

**Состояние** s — 64 бита, начально `task_seed × 1000 + i`.

**`next()`:**

1. s ← s + 0x9E3779B97F4A7C15;
2. z ← s;
3. z ← (z ⊕ (z ≫ 30)) × 0xBF58476D1CE4E5B9;
4. z ← (z ⊕ (z ≫ 27)) × 0x94D049BB133111EB;
5. вернуть z ⊕ (z ≫ 31).

Всё по модулю 2⁶⁴. `below(n)` = `next() mod n`.

**СЛОВА** (20, по номерам 0…19): река, мост, город, свет, ветер, дорога,
камень, окно, берег, поле, лес, гора, море, небо, дом, сад, путь, огонь,
снег, трава.

**Порядок генерации** для контура i — ровно такой:

1. **Каждая сортировка:** 64 раза `below(1000)` — числа.
2. **Каждый поиск:**
   1. 64 раза `below(16)` — числа;
   2. затем `below(10)`:
      - если < 8 — искомое = `below(16)`;
      - иначе искомое = 16 + `below(4)`.
3. **Каждая таблица:** table_rows × table_cols раз `below(100)`, по строкам.
   - Часть p из k содержит строки с ⌊p·r/k⌋ по ⌊(p+1)·r/k⌋ − 1.
4. **Каждый документ:**
   1. a = `below(20)`, b = `below(19)`; если b ≥ a, то b ← b + 1. A =
      СЛОВА[a], B = СЛОВА[b].
   2. Для каждого из doc_sections разделов:
      - doc_words раз `below(20)` — слова;
      - затем слово с номером `below(doc_words)` заменить на A;
      - раздел = слова через пробел, первая буква заглавная, в конце
        точка.
   3. Часть p из k — разделы с ⌊p·S/k⌋ по ⌊(p+1)·S/k⌋ − 1, соединённые
      `"\n\n"`.

## 11.3. Верный ответ и проверка

| Вид | Верный ответ |
|---|---|
| сортировка | те же числа по неубыванию, 4n байт |
| поиск | если искомого нет — −1; иначе номер вхождения. При canonical = 1 верно только **первое**, при 0 — любое. Ровно 4 байта |
| таблица | суммы по столбцам, затем общая сумма; 4(c + 1) байт |
| документ | текст, где каждое вхождение A заменено на B: слева направо, без перекрытий |

Иная длина ответа — неверно.

**Объём проверки** w:

- сортировка — n;
- поиск — n, если ответ ровно 4 байта со значением −1, иначе 1;
- таблица — r × c;
- документ — длина текста.

**Стоимость проверки** v = max(1, ⌈w / check_unit⌉).

## 11.4. Варианты

- **M0** — §10.3, остаток бесконечен.
- **M2** — §10.3, растущая цена.
- **M1, M3** — постоянные цены. Различие M0–M2 и M3 — в настройках графа
  (levels), а не в правиле.

## 11.5. Сдача ответа (оп 8 на свой выход)

**Отказ сдачи:**

- списать min(c_отк, max(остаток, 0)), при M0 — c_отк;
- записать `{"kind": "отказ", "contour": i, "subject": S, "fix": №,
  "receiver": "выход", "msg": "", "charge": …, "why": причина, "task": t,
  "part": p}`;
- вернуть код.

**Протокол:**

1. Граница — иначе −4. Сообщение — байты [a, a+b).
2. Выделить номер (§10.3).
3. Точка «в начале фиксации».
4. t, p — первые два байта, если длина ≥ 2, иначе −1 и −1. Ответ —
   остальное.
5. Нет части (t, p) — отказ, причина `"нет такой задачи"`, код −6.
6. Часть уже **принята** — отказ, причина `"уже принято"`, код −6.
   Принята — значит, в журнале контура есть «списание» с этими task, part
   и номером, для которого есть «завершено».
7. **Плательщик:** `"агент"`, если в журнале контура есть «отказ» с этими
   task, part и `"why": "ответ неверен"`; иначе `"среда"`.
8. v — §11.3, P — цена фиксации (§10.3).
9. Остаток < P + (v, если платит агент) — отказ, причина `"мало
   бюджета"`, код −3.
10. Записать `{"kind": "проверка", "contour": i, "subject": S, "fix": №,
    "task": t, "part": p, "payer": плательщик, "price": v, "length": длина
    ответа}`. Если платит агент — списать v.
11. Неверно — отказ, причина `"ответ неверен"`, код −6. **Место ошибки не
    сообщать.**
12. Точка «перед списанием».
13. Списать P. Записать «списание» как в §10.3, с `"receiver": "выход"`,
    `"msg": "задача {t}.{p}: {ответ строчными шестнадцатеричными}"`,
    `"task": t`, `"part": p`. Оборванная — «запись списания оборвана».
14. Точка «после списания».
15. Получатель «выход». Оборванная — «запись доставки оборвана».
16. Точка «после доставки».
17. «завершено».
18. Эффект:
    - дописать байты ответа в данные `выход{i}`, обрезав до 4096;
    - метки ∪= метки памяти;
    - действие «сдача ответа».
19. Вернуть 0.

Поле `charge` пишется, только если плата не ноль. Поля `gate_price` и
`check_price` попадают в запись «учёт», только если они не по умолчанию;
при восстановлении отсутствующее поле значит «по умолчанию». Поэтому при
прежних ценах журнал побайтно прежний.

**spawn.** Предел экземпляров (§7) — проверка вызова, как переполнение
ссылок и объектов: он проверяется **до бюджета**. Если упираются оба —
отказ −5, а не −3. Плата списывается до создания помощника: его
стартовая функция тратит уже уменьшенный бюджет. Если помощник не
создался по ошибке движка (−5, §14), плата возвращается, записи нет.

**Расход** (§12, `spent`) включает поля `charge`. Наблюдатель проверяет
закон И31р: у каждой такой записи плата равна g, умноженной на число её
записей.

# 16. Попытка платит (шаг 8в)

Добавлено после шага 8б. Устройство и причины — спецификация шага 8в.

**Настройка** (§2), по умолчанию — прежнее поведение:

| Поле | По умолчанию | Смысл |
|---|---|---|
| paid_attempts | 0 | 1 — правило этого раздела включено |

Отказ команды `new` (§1), если `paid_attempts` не 0 и не 1, или если он
1, а хоть одна из цен `gate_price`, `price`, `fail_price`, `work_price`
меньше 1. В запись «учёт» поле попадает, только если оно 1; при
восстановлении отсутствующее поле значит 0. При `paid_attempts` = 0 всё
ниже не действует и журнал побайтно прежний.

**Попытка** — каждый вызов `call` или `spawn` экземпляром X контура i
(агентом `а{i}` или помощником `п{i}`). S — субъект X.

**Шаг 0 попытки** — раньше §10.1 и раньше всех проверок `spawn` (§7, §15):

1. Контур уже остановлен — ловушка «бюджет исчерпан». Записи нет,
   счётчик отказов не меняется.
2. Остаток контура (§10.3, «Остаток агента») ≤ 0 — записать
   `{"kind": "останов", "contour": i, "subject": S, "why": "бюджет исчерпан"}`,
   пометить контур остановленным, ловушка «бюджет исчерпан». При
   `rule = "M0"` остаток бесконечен, и этот пункт не срабатывает.

**Ловушка «бюджет исчерпан»** обрывает весь вызов, как ловушка движка:

- в `run` — исход `["ловушка", "бюджет исчерпан"]`;
- в стартовой функции при `load` — как любая ловушка там (§14): исход
  `["ловушка", "бюджет исчерпан"]`, запись «загрузка: ловушка» с
  `"reason": "бюджет исчерпан"`;
- в помощнике — ловушка всего вызова, породившего его (§7).

**Стартовая функция помощника.** Пока помощник создаётся (`spawn`, §7),
плата 2g за него уже списана (§15), и остаток мог стать 0 только из-за
неё. Поэтому:

- попытка стартовой функции помощника при остатке ≤ 0 **не останавливает
  контур**: создание обрывается, плата 2g возвращается, записей о
  создании нет, `spawn` возвращает **−3**, и этот отказ платит, как любой
  («отказ ворот» с `"call": "spawn"`). Остаток после возврата больше 0,
  поэтому плата не меньше 1. Записи, которые стартовая функция успела
  сделать до этого, остаются;
- любая другая ловушка в стартовой функции помощника (ловушка движка) —
  помощник тоже не создан: плата 2g возвращается, записей о создании нет,
  но ловушка обрывает весь вызов. Это действует и без правила §16.

Пометка «остановлен» живёт, пока жив исполнитель; восстановлением не
переносится (§10.6): агента после восстановления нет, а новый агент при
остатке ≤ 0 остановится на первой попытке, с новой записью «останов».

**Отказ платит.** Если попытка кончилась отрицательным возвратом и **не
записала свой отказ** — запись «отказ» фиксации (§10.3, шаг 3) или сдачи
ответа (§11.5), — то после всего прочего:

1. списать min(g, остаток), при `rule = "M0"` — g;
2. записать для `call`:
   `{"kind": "отказ ворот", "contour": i, "subject": S, "call": "call", "cap": номер, "op": оп, "code": возврат, "charge": списано}`;
   для `spawn`: те же поля без `cap` и `op` и с `"call": "spawn"`.

Номер и операция — как их передал агент. Остаток в начале попытки был
больше 0 (шаг 0), поэтому списано всегда не меньше 1. Счётчик отказов
(§12) считает возврат, как прежде.

Отказы, которые пишут свой «отказ», платят, как прежде: min(c_отк,
остаток). Успешные вызовы платят, как в §15. С правилом все цены не
меньше 1, поэтому у каждой попытки, которая не остановила контур, плата
не меньше 1.

**Восстановление** (§10.6): в расход контура входит и `charge` записей
«отказ ворот».

**Законы**, которые проверяет наблюдатель:

- **И32р** — с последнего «открыт» или «восстановлено» отказов в счётчике
  контура (§12) столько же, сколько записей «отказ ворот» и «отказ»
  этого контура; у каждого «отказа ворот» плата g, кроме случая, когда
  после него остаток 0;
- **И33р** — после «останова» контура и до «восстановлено» нет записей с
  его субъектами; «останов» пишется только при остатке ≤ 0 и не больше
  одного раза до «восстановлено»;
- при `paid_attempts` = 0 нет ни «отказа ворот», ни «останова».

# 17. Вопрос модели (шаг 9)

Добавлено в шаге 9. Устройство и причины — спецификация шага 9. Выполняют
обе реализации.

**Настройки** (§2), по умолчанию — прежнее поведение:

| Поле | По умолчанию | Смысл |
|---|---|---|
| model | 0 | 0 — модели нет; 1 — модель снаружи; 2 — модель на устройстве (§18) |
| model_answer | 1024 | A — предел ответа модели, байт |
| model_byte_unit | 0 | U — байт вопроса и ответа на единицу бюджета; 0 — платы за байты нет |

Отказ команды `new` (§1), если `model` не 0, не 1 и не 2, если
`model_answer` вне [1, 4096], если `model_byte_unit` меньше 0 или если
`model` не 0, а модель при запуске исполнителя не подключена. В запись «учёт» поля попадают, только если не по умолчанию; при
восстановлении отсутствующее поле значит «по умолчанию». При `model` = 0
всё ниже не действует, и журнал побайтно прежний.

**Подключение модели** — параметр запуска исполнителя, а не команда:
`--model=РЕЖИМ` (`--stub` или `--gguf ФАЙЛ`) и `--model-timeout=С`
(по умолчанию 120); каждый одним словом — см. уточнения в конце параграфа. На каждый контур — свой процесс модели, без сети,
запущенный до первой команды. Обмен с ним — строки JSON:
`{"q": base64 вопроса, "max": A}` → `{"a": base64 ответа}`.

**Объект** `модель{i}` (§6) — у каждого контура свой. Номер в начальной
таблице агента — **последний**: 7 при `--kind 5б`, 8 при `--kind 6` (после
`задания{i}`); право «выз». Прежние номера не сдвигаются.

**Справочник** (§10.1, оп 2 на `резольвер`): имя «модель» → значение
`model`. При `model` = 0 имени нет (−2).

**Ход:** оп 2 («вызов») на `модель{i}` своего контура с правом «выз».
Другая операция на этот номер — −1. Порядок разбора, после общих шагов
§10.1 и шага 0 попытки (§16):

1. нет экспортированной памяти `memory` или [a, a+b) вне её — **−4**;
2. b = 0 — **−6**;
3. b > 4096 — **−5**; вопрос не обрезается;
4. a + A больше длины памяти — **−4**: ответ некуда положить;
5. процесс модели мёртв или не подключён — **−7**;
6. бюджет: плата **p = 2g + ⌈(b + A) / U⌉** (при U = 0 — 2g): две записи
   журнала (§15) и байты вопроса с пределом ответа — длина ответа до
   отправки неизвестна. Не хватает — **−3**;
7. записать `"действие"`: правило «вопрос модели», объект `модель{i}`,
   факты `["сведения", "модель{i}", x]` по меткам памяти контура,
   `"charge": p` (если не 0), `"question"`: текст вопроса (UTF-8 или
   «0x…», как у фиксации, §10.2), `"length"`: b;
8. метки `модель{i}` ∪= метки памяти контура;
9. отправить вопрос, ждать ответа не дольше срока;
10. ответа нет в срок (или процесс умер) — процесс убить; записать
    `"действие"`: правило «ответ модели», объект `модель{i}`, факты `[]`,
    `"answer": null`, `"code": −7`; вернуть **−7**. Это отказ со своей
    записью: «отказа ворот» после него нет (§16). Дальше этот контур
    получает −7 на шаге 5;
11. иначе ответ обрезать до A байт, записать в память агента с адреса a,
    метки памяти ∪= {«М»}; записать `"действие"`: правило «ответ модели»,
    объект `модель{i}`, факты `[["сведения", "память{i}", "М"]]`,
    `"answer"`: текст, `"length"`: длина; вернуть длину ответа.

Слова модели не дают прав: ни одно содержимое ответа ничего не меняет в
таблицах (как слова человека, §7).

**Восстановление** (§10.6): плата вопроса — в `charge` записи «вопрос
модели», расход её включает. Модель заново не спрашивается: агент сбоя
не переживает (§9), и переспрашивать некому.

**Опись** (§8): подписи `["вопрос модели", "модель", "свой"]` и
`["ответ модели", "модель", "свой"]`.

**Законы**, которые проверяет наблюдатель:

- **И31р** — у «вопроса модели» плата p, у «ответа модели» поля `charge`
  нет;
- **И32р** — «ответ модели» с полем `code` считается записанным отказом;
- **И34р** — за каждым «вопросом модели» сразу следует «ответ модели» того
  же субъекта, перед каждым ответом — вопрос; длина вопроса от 1 до 4096;
  ответ не длиннее A; ответа нет — только с кодом −7; при `model` = 0 нет
  ни одной такой записи.

**Уточнения после второй реализации (§17).** Места, где §17 молчал. Второй
автор решил их под замком, и в каждом выбрал то же, что первая реализация.
Это показали различающее сравнение на случаях шага 9 и прямые проверки
краёв (отчёт `shag9_vtoraya_otchet.md`). Теперь это правила контракта.

| Место | Правило |
|---|---|
| Параметры запуска | `--model=РЕЖИМ` и `--model-timeout=С` — каждый одним словом: режим начинается с «--», и раздельное значение разборщик принял бы за новый параметр. Какую программу запускать процессом модели, решает запуск, а не контракт: обвязка судьи даёт путь в переменной `MODEL_SERVE`; это исполняемый файл, и исполнитель запускает его сам (§18.1) |
| Жизнь процесса модели | процесс принадлежит исполнителю, а не запуску: `new`, `recover`, `restart` его не перезапускают. Умерший или замолчавший процесс мёртв до конца жизни исполнителя |
| `recover` при `model` = 1 без подключённой модели | разрешён: отказ по подключению — только у `new`. Вопросы получают −7 на шаге 5 |
| Ответ не по протоколу | не JSON, нет поля `a` или неверный base64 — то же, что «ответа нет» (шаг 10): процесс убит, «ответ модели» с кодом −7 |
| Шаг 1 при b = 0 | [a, a) в памяти, если 0 ≤ a ≤ длины памяти; тогда дальше шаг 2 (−6). При a вне этих границ — −4 |
| Другая операция на номер модели | −1 и у модуля без памяти: номер разбирается раньше проверки памяти |
| Пустой ответ | метка «М» добавляется; в память ничего не пишется; длина 0 |
| Обрезка ответа до A | по байтам; если обрезка рассекла знак UTF-8, текст ответа в журнале — «0x…» (как у фиксации, §10.2), длина — после обрезки |
| `model_answer` и `model_byte_unit` при `model` = 0 | проверяются всегда; не по умолчанию — попадают в «учёт» |

**Уточнение шага 9б (§17).** Найдено при подготовке захода §18: реализации
читали шаг 5 по-разному, и журнал второй зависел от времени.

| Место | Правило |
|---|---|
| Процесс модели умер сам | исполнитель узнаёт о смерти процесса только вопросом. «Мёртв» на шаге 5 — убит исполнителем на шаге 10 (срок вышел, процесс умер, ответ не по протоколу). Процесс, умерший сам, на шаге 5 ещё считается живым: первый вопрос к нему идёт шагами 6–10 — плата, «вопрос модели», затем «ответ модели» с −7; следующие получают −7 на шаге 5. Так журнал не зависит от того, когда процесс умер. Проверка у судьи — случай «модель умерла сама» набора шага 9, закон «К17» |

# 18. Модель на устройстве (шаг 9б)

Добавлено в шаге 9б. Устройство и причины — спецификация шага 9б
(`shag9b_specifikatsiya.md`). Выполняет первая реализация; вторая — после
захода под замком.

**Настройка.** `model` = 2 — модель на том же устройстве, что и агент.
Раньше значение 2 отвергалось.

**Ворота не меняются.** При `model` = 2 действует всё, что §17 говорит о
`model` = 1: ход «спросить модель», порядок разбора, записи «вопрос
модели» и «ответ модели», метки, коды отказов, плата, срок ответа, жизнь
процесса модели, уточнения таблицы §17. Отличий два, и оба — значение:

- в записи «учёт» поле `"model": 2`;
- справочник на имя «модель» отвечает 2.

На одной и той же программе журналы режимов 1 и 2 различаются только этим
полем записи «учёт» и, следом, отпечатками цепочки (§4). Выгрузка не
различается. Исключение одно, и оно не от ворот: всё, что агент сам
сделал с ответом справочника. Справочник возвращает номер режима кодом
возврата; если агент записал его в память, в вопрос модели или в
сообщение, там он и будет другим.

**Условие режима 2: процесс модели запущен исполнителем на этом же
устройстве и без сети.** Этим режим и отличается по смыслу: вопрос модели
в нём не вывод наружу, а работа модели — расход устройства.

- Чем обеспечено «без сети», зависит от устройства и задаётся параметром
  запуска `--model-net` (ниже), а не командой: словами человека, ходом
  агента или ответом модели способ не меняется.
- Исполнитель, который умеет подключить модель с сетью, отвечает отказом
  на `new` с `model` = 2 при такой модели. То же — на `recover` и
  `restart` журнала с `model` = 2. У первой реализации такое подключение
  есть только в тестах.
- `recover` и `restart` при `model` = 2 без подключённой модели разрешены,
  как при `model` = 1: вопросы получают −7 на шаге 5.

**Срок ответа** — тот же параметр запуска `--model-timeout`. В режиме 2
он входит в предел расхода устройства (спецификация шага 9б, §4), и его
значение берут из калибровки устройства. Поведение по сроку прежнее.

## 18.1. Способ «без сети»: параметр `--model-net`

**Параметр запуска** `--model-net=СПОСОБ` — одним словом, как `--model`
(§17). Способов два: `netns` (по умолчанию) и `probe`. Без `--model`
параметр не действует: изолировать нечего. Другое значение — исполнитель
не запускается.

**Программа процесса модели** — исполняемый файл; путь даёт запуск
(у судьи — переменная `MODEL_SERVE`). Исполнитель запускает этот файл
сам, с аргументами режима из `--model` (`--stub`, `--gguf ФАЙЛ` и т. п.),
а не через `python3`: на телефоне это родная программа, и Python там нет.

| Способ | Где | Как запускается процесс модели |
|---|---|---|
| `netns` | Linux: сервер, компьютер | `unshare -rn ПРОГРАММА РЕЖИМ…` — у процесса своё пустое сетевое пространство. `unshare -rn` не работает — исполнитель не запускается |
| `probe` | Android: у приложения нет разрешения на сеть | сначала проба (ниже); прошла — `ПРОГРАММА РЕЖИМ…` напрямую, `unshare` не вызывается; не прошла — исполнитель не запускается |

**Проба** — до запуска процессов модели и до первой команды. Исполнитель
четырежды пробует создать сокет функцией `socket()` библиотеки C: семейства
IPv4 и IPv6, виды потоковый и датаграммный. Годится один исход: **все
четыре** попытки отказаны с ошибкой «нет права» — `EACCES` или `EPERM`.
Тогда сети нет ни у исполнителя, ни у его дочерних процессов, пока жив
процесс, и процесс модели считается запущенным без сети: режим 2
разрешён. Любой другой исход проба не принимает:

- сокет создался — его закрыть; маршрута может и не быть, но Wi-Fi может
  вернуться в любую минуту;
- ошибка не «нет права» (например, «семейство не поддержано») — её смысл
  пробе неизвестен.

**«Не запускается»** — процесс исполнителя завершается с кодом не 0 и не
17, не ответив ни на одну команду; причина — в поток ошибок.

**Процесс модели умирает вместе с исполнителем** — при любой смерти
исполнителя: обычном конце, сбое по инъекции (код 17), убийстве. Это
обеспечивает система, а не процесс модели и не исполнитель, которого уже
нет: дочерний процесс до запуска программы модели просит систему убить его
при смерти родителя (на Linux и Android — `prctl(PR_SET_PDEATHSIG,
SIGKILL)`; настройка переживает запуск программы и `unshare`). Иначе
процесс, занятый вопросом, досчитывал бы его после смерти исполнителя: на
телефоне это минуты полной нагрузки вне предела устройства и вне сторожа
(спецификация шага 9б, §5–§6). Действует при обоих способах.

**Почему `EACCES` или `EPERM`.** На Android отказ в сокете приложению без
разрешения на сеть даёт система: прежний запрет ядра (группа inet) отвечает
`EACCES`, нынешний (программа ядра, которая смотрит разрешение
приложения) — `EPERM`. Какой из них на телефоне шага, показывает малый
стенд.

**Чего проба не видит:** местные каналы между процессами устройства
(сокеты внутри устройства, общие файлы). Что программа модели ими не
пользуется, показывает прибор на сервере (strace), а не проба
(спецификация шага 9б, §9).

**Проверка у судьи:**

- `--suite net` — закон «К18»: проба на сервере, где сокеты создаются, не
  проходит; строгость (отказан только IPv4, только IPv6, только потоковый,
  отказ не «нет права» — не проходит); при отказе «нет права» исполнитель
  запускается, процессов модели два, их сетевое пространство — то же, что у
  исполнителя, `unshare` не вызывается, процесс модели — программа из
  `MODEL_SERVE`, модель отвечает; при `netns` у процесса модели своё
  сетевое пространство; `--model-net` без `--model` не действует;
  исполнитель убит, пока модель занята вопросом, — через 2 с ни одного
  живого процесса модели (обоими способами);
- `--suite 9 --model-mode 2 --model-net probe` — случаи шага 9 при
  способе probe.

Отказ «нет права» на сервере изображает подменная `socket()` судьи
(`judge/model9/nosock.c`, через `LD_PRELOAD`). Она видит только функцию
библиотеки C, поэтому проба — этой функцией, а не прямым системным
вызовом. Журнал от способа не зависит: на одной программе журналы при
`netns` и `probe` совпадают байт в байт.

**Законы.** Все прежние действуют без изменений; И34р — как при
`model` = 1. Наблюдатели режимы 1 и 2 не различают.

**Проверка у судьи:** `--suite 9 --model-mode 2` и
`--suite attempts9 --model-mode 2`. Случаи те же, что для режима 1.
