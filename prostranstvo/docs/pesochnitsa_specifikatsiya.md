# 1. Зачем

Шаги 1–9б проверяли среду прогонами, которые запускает автор: сценарии,
порчи, наблюдатели. Песочница «из коробки» даёт то же самое любому, кто
скачал ветку: одна команда — и в браузере экран, на котором человек
выбирает модель, пишет агенту слова и смотрит, что агент делает и
держатся ли законы среды.

**Решения владельца (18.11.2026):**

- сначала компьютер, потом телефон;
- переключатель между **сомкнутым** контуром (модель на этом же
  устройстве — для местных моделей) и **разомкнутым** (модель снаружи —
  для облачных);
- на телефоне — два приложения: песочница без права на сеть и отдельная
  маленькая «связь» с правом на сеть только для облачной модели (§10);
- собранное (APK и т. п.) — во вкладку Releases на GitHub, не в историю
  ветки;
- цвета — из приложения агента.

**Поправки владельца (19.11.2026)** по первым снимкам экрана:

- экран и описание — на двух языках (русский и английский), с
  переключателем;
- названия сценариев — понятные стороннему человеку, с пояснением, что
  каждый проверяет;
- ни «наших» моделей, ни демо на экране: любая модель-файл GGUF (путь на
  диске или ссылка на скачивание) или облако;
- от агента — только цвета, раскладка своя (не копия интерфейса агента);
- кнопка остановки подписана тем, что она делает, и видна только во время
  прогона;
- каждый ход объяснён словами: что предложила модель, что это значит, что
  сделала среда; законы — простым языком.

Песочница не добавляет к среде новых ходов, законов и цен. Исполнитель,
агент, ворота, плата и наблюдатели — те же, что проверены в шагах 5–9б.
Новое — запуск, экран, печать сети и связь с облаком.

# 2. Кто где

| Часть | Что | В основании доверия? |
|---|---|---|
| `start.py` | готовит окружение (свой venv, wasmtime, сборка агента) и запускает экран | нет: он ничего не решает за среду |
| экран (`app/server.py`, `app/ui`) | ведущий: передаёт исполнителю слова и настройки, показывает журнал | **нет** — недоверенный ведущий, как в шаге 5 (`Driver`) |
| исполнитель | `sandbox/process5.py` и `executor5b/6.py` — первая реализация, без изменений | да |
| печать сети (`app/seal.py`) | фильтр системы на процесс исполнителя: создать сетевой сокет нельзя | **да** — новое в основании |
| агент | `experiments/agents9/agent9.c` → WebAssembly, без изменений | нет |
| процесс модели, сомкнутый контур | `model9/serve.py --gguf` (или `--script` для проверки установки) | нет: не действует, ответ — данные |
| передатчик, разомкнутый контур | `model9/serve.py --relay` — тот же процесс модели, только ответ берёт у связи | нет |
| связь (`app/bridge.py`, `app/cloud.py`) | в процессе ведущего: принимает вопрос от передатчика, отправляет облаку, возвращает ответ | **да** для разомкнутого контура: через неё вопрос уходит наружу |
| облачная модель | сервис поставщика | нет; её инертность — обещание поставщика (§9) |

Исполнитель и его процессы модели живут под печатью сети в **обоих**
контурах. Сеть есть только у ведущего: экран слушает адрес 127.0.0.1, а
связь в разомкнутом контуре ходит к облаку. Из песочницы до облака один
путь: ворота → переходник → передатчик → связь.

# 3. Переключатель контуров

Переключатель — настройка запуска (решение 13.11, A10): агент видит режим
справочником («модель» → 1 или 2), но поменять не может; другой контур —
новый запуск.

| | Сомкнутый (`model = 2`) | Разомкнутый (`model = 1`) |
|---|---|---|
| где модель | процесс на этом компьютере | у поставщика (или в другой программе: Ollama, LM Studio) |
| сеть у процесса модели | отнята системой (печать, §4) | у передатчика нет; у связи есть |
| куда уходит вопрос | никуда с компьютера | к поставщику — второй разрешённый вывод (шаг 9, §1) |
| чем ограничена работа модели | счёт вопросов (бюджет) и срок ответа — вариант «а» шага 9б | то же |
| цена вопроса | прежняя: 2g + ⌈(b + A) / U⌉, из бюджета | та же |
| И35р (ответ зависит только от вопроса) | свойство программы модели: жадный выбор, без памяти | не гарантируется: облако не обязано отвечать одинаково (§9) |

Проверка установки (`start.py --check`, `serve.py --script`) — сомкнутый
контур без файла модели: заранее записанные ходы, среди них попытки
выхода. Это прибор для установки и тестов, а не модель: на экране его нет
(решение владельца 19.11 — на экране только своя модель или облако).

Модель-файл — любой GGUF: из папки `models`, по пути на диске или по
ссылке (ссылка Hugging Face на страницу файла превращается в ссылку на
сам файл). Скачанный файл проверяется по началу («GGUF»), его хеш SHA-256
показывается человеку, но не сверяется: для произвольной ссылки сверять
не с чем.

**Предел устройства** (шаг 9б, §4.3) на компьютере не считается: он
калиброван для телефона. На компьютере работу модели держат счёт вопросов
и срок ответа.

# 4. Печать сети

**Что это.** Фильтр системного вызова (seccomp, Linux): процесс
исполнителя ставит его себе до запуска процессов модели. После этого
`socket()` для любого семейства, кроме местного (AF_UNIX), отвечает
«нет права» (EPERM); создание `io_uring` — тоже (через него сокет
создаётся в обход `socket()`); вызовы чужой разрядности (x32) — тоже.
Фильтр наследуется всеми дочерними процессами и не снимается.

В **сомкнутом** контуре закрыто и AF_UNIX: процессу модели местные
каналы не нужны. В **разомкнутом** AF_UNIX открыт — по нему передатчик
говорит со связью.

**Зачем печать, если есть `unshare -rn`.** Пустое сетевое пространство
требует пространств пользователя, а их запрещают некоторые системы
(Ubuntu 24.04 по умолчанию). Печать работает на любом ядре Linux с
seccomp (с 3.17 — с TSYNC). Проверка та же, что на телефоне: строгая
проба §18 (`--model-net probe`) — все четыре сетевых сокета обязаны
получить «нет права». Печать для пробы — то же, что для телефона
отсутствие права на сеть: система отказывает сама.

**Порядок выбора.** Печать → иначе пустое сетевое пространство
(`unshare -rn`, только для процесса модели) → иначе сомкнутый контур
**не запускается**. Разомкнутый без печати запускается с пометкой на
экране и в итогах: «печать сети не поставлена — песочницу держит только
устройство ворот».

**Чего печать не умеет:**

- она только для Linux на x86_64 и aarch64; на других — §8;
- в разомкнутом контуре местные каналы (AF_UNIX) открыты процессам
  исполнителя — проба их не видит (так же, как на телефоне, контракт §18);
- уже открытых сетевых соединений она не закрывает — у исполнителя их
  нет: он запускается чистым процессом (`spawn`), с одним каналом к
  ведущему;
- побочные каналы (время ответа, общий процессор) она не закрывает.

# 5. Связь с облаком

**Протоколы:** OpenAI-совместимый (`POST …/chat/completions`) — OpenRouter,
DeepSeek, Groq, Mistral, OpenAI, Ollama и LM Studio на этом же компьютере
и многие другие; Anthropic (`POST /v1/messages`). Вопрос уходит одним
сообщением пользователя, как есть, без системной подсказки: что спросить,
решает агент, а не ведущий. Температура 0. Беседы на стороне поставщика
нет: каждый вопрос самостоятелен (модель без памяти, шаг 9, §3).

**Сколько токенов на ответ.** Половина предела ответа A, как у местной
модели (`serve.py`): ответ длиннее A всё равно обрежет исполнитель.
Настройка на экране — для моделей с рассуждением, которым мало.

**Ключ** вводится на экране или берётся из переменной окружения. Живёт
только в памяти ведущего: не пишется ни в журнал, ни в файлы прогона, ни
в настройки; исполнителю и процессам модели не передаётся.

**Сбой облака.** Связь повторяет вопрос при 429 и 5xx с паузами в
пределах срока ответа. Не вышло — связь закрывает канал передатчику: тот
выходит, исполнитель получает молчание, вопрос — отказ −7 своей записью
(как у местной модели, контракт §17), переходник больше не отвечает. Ответ
с текстом ошибки агенту не подаётся: слова, которых модель не говорила, —
подмена. Причину сбоя экран показывает человеку.

**Проверка связи** — до запуска, одним коротким вопросом мимо песочницы:
неверный ключ или имя модели видны сразу, а не после десяти минут
прогона. В журнал она не попадает: это не ход агента.

**Плата.** Вопрос платит из бюджета, как всякий вопрос. Деньги
поставщика — отдельно; экран показывает токены, которые насчитал
поставщик.

# 6. Что видит человек

- **Строка хода под заголовком** меняется, пока идёт шаг: что делается и
  сколько секунд (урок промаха № 51: застывшая строка читается как
  «висит»).
- По каждому агенту: остаток бюджета, вопросов, байт к модели, ходы
  списком (ход модели и итог ворот), отказы по кодам, принятые части
  задач. Вопрос и ответ целиком — по нажатию.
- **«Остановить прогон»** убивает исполнитель и процессы модели сразу, не дожидаясь
  конца хода (урок № 52). Журнал до остановки остаётся.
- **Итог** — законы наблюдателей шага 6 (`observer6.check`, 41 пункт
  вместе с мерами), по-человечески сгруппированные: «выхода наружу нет»,
  «контуры не сообщаются», «права не берутся из слов», «всё оплачено и
  записано», «узлы и доставки по правилам», «полезная работа честная»,
  «исполнитель жив». Описания законов берутся из словарей наблюдателей,
  а не пишутся второй раз.
- Прибор аудита процесса исполнителя (шаг 5): пусто — значит, исполнитель
  не трогал файлов вне своей папки, сети и процессов.
- Журнал и итоги прогона — одним zip.

Раскладка своя, для компьютера: настройка слева в три шага (модель, что
проверить, параметры и запуск), прогон справа; на узком экране — одно под
другим. Кнопка «Остановить прогон» — рядом со строкой состояния и только
пока прогон идёт.

Каждый ход показан трижды: что ответила модель (как есть), что этот ход
значит (по ключевому слову), что сделала среда (по записям журнала: ✓, ✗
с причиной, служебное); отдельно, курсивом, — как итог понял сам агент
(строка истории в его следующем вопросе: это слова агента, а не запись
среды).

Два языка: строки экрана — в самой странице; сценарии и законы простыми
словами — в `app/texts.py` (точные формулировки законов остаются в
словарях наблюдателей). Сервер шлёт данные, а не фразы: события журнала —
полями записи, заметки — кодом, отказы настроек — сразу двумя текстами.

Цвета — из приложения агента (только цвета): фон #EAF3F6, карточки белые, текст #123540,
второстепенный #3A6470, приглушённый #7FA3AE, главный #17697B, остановка
#D6453E, тревога #FBE3E1 / #A3231D, слова модели — #5B4B9E (в агенте этим
цветом помечено содержимое другого рода, чем лог), неприменимое — #FCE8B8.

**Экран — для одного человека на своём компьютере.** Слушает только
127.0.0.1. Каждый запрос несёт метку, выданную при запуске (она в ссылке,
которую печатает `start.py`), и проверяется имя хоста: чужая вкладка
браузера не запустит прогон на чужом ключе.

# 7. Проверки (объявлены до кода)

| Что | Как | Вердикт |
|---|---|---|
| печать, сомкнутый | дочерний процесс под печатью пробует сокеты | INET, INET6, UNIX, NETLINK, PACKET — EPERM; `io_uring_setup` — EPERM; строгая проба §18 проходит |
| печать, разомкнутый | то же | сетевые — EPERM; AF_UNIX создаётся |
| без печати | прогон сомкнутого контура с выключенной печатью и без `unshare` | отказ запуска, а не прогон «как будто без сети» |
| порча печати | фильтр, пропускающий AF_INET | проба §18 не проходит → сомкнутый отказ |
| передатчик и связь | облако-заглушка (местный HTTP, оба протокола) | вопрос и ответ в журнале байт в байт; И34р держится |
| сбой облака | заглушка отвечает 500 всегда | вопрос — отказ −7 своей записью; дальше −7 без отправки; законы держатся |
| ключ | прогон с ключом-меткой | метки нет ни в одном файле прогона и ни в одном аргументе процессов |
| проверка установки | записанные ходы | все применимые законы держатся; аудит пуст; ход `ВЫЗОВ` дал отказ ворот, а не право |
| тексты | все законы прогона и все сценарии | каждый закон — в группе экрана и пересказан на двух языках; слова сценариев влезают в 600 байт |
| ссылка на модель | страница файла Hugging Face; не https; не .gguf | ссылка на файл; отказ; отказ |
| стоп посреди хода | заглушка, отвечающая через 30 с; «Остановить прогон» на 3-й секунде | исполнитель и процессы модели мертвы за 2 с; журнал на месте |
| экран | запросы без метки, с чужим Host | 403 |
| с нуля | чистая папка, `python3 start.py --check` | окружение собирается, проверка установки даёт «законы соблюдены» |

# 8. Чего песочница не умеет

- **Только Linux** (x86_64, aarch64); Windows — через WSL2. macOS не
  поддерживается: там нет ни seccomp, ни `prctl` (процесс модели умирает с
  исполнителем через `prctl`).
- Облачная модель может помнить вопросы, учиться на них, иметь
  инструменты на своей стороне — это обещание поставщика, а не свойство
  среды (шаг 9, §9). Среда гарантирует только, что ответ — данные: он
  ничего не меняет в таблицах прав (И24р).
- Канал к модели широкий: всё, что агент написал в вопрос, уходит
  поставщику. Он учитывается (байты, метки), но не сужается.
- Время ответа модели — побочный канал, не закрыт (класс 4).
- Вторая реализация (Rust) в запуске не участвует: экран гоняет первую.
  Сверка реализаций — `run_shag9b_vtoraya.py`.
- Экран не многопользовательский и не для сети: только 127.0.0.1.
- Агент — один, наш (`agent9`): свои модули WebAssembly экран не
  принимает (это следующий шаг, если понадобится).
- Слова человека агент читает до 600 байт (около 300 русских букв):
  длиннее — обрезаются им самим; экран показывает счётчик.

# 9. Что гарантируется в разомкнутом контуре и что нет

Гарантируется средой (то же, что в шагах 5–9б): у агента нет полномочия
наружу, кроме вопроса модели; вопрос оплачен и записан **до** отправки;
ответ не длиннее A и ложится в память агента с меткой «М»; слова модели
прав не дают; контуры не сообщаются через среду.

Не гарантируется: что поставщик не хранит вопросы; что одна облачная
модель не связывает вопросы двух контуров у себя (общий сервис — класс 1
инцидентов, «доска объявлений»; шаг 9, §3). Поэтому в разомкнутом
контуре **закон И22р проверяет среду, а не поставщика**: если оба агента
спрашивают одну облачную модель, связь между ними через поставщика среда
не видит. На экране это сказано рядом с итогом.

# 10. Телефон (следующий шаг)

Право на сеть Android даёт приложению целиком и один раз — при установке;
от запуска к запуску оно не переключается. Поэтому «песочница включена —
сети нет» системой держится только в приложении, у которого этого права
нет вовсе. Отсюда два приложения: «Пространство» (без права на сеть,
переключатель в нём) и «Пространство · связь» (право на сеть, ключ,
передача вопросов). В сомкнутом контуре «связь» не вызывается. Устройство
передачи между ними — в спецификации телефонной части.

# 11. Прогон по CHECKLIST.md

| Пункт | Ответ |
|---|---|
| 1. Цена и безопасность | Платим новым звеном в основании доверия — связью — и вторым разрешённым выводом наружу через настоящую сеть. Порядок: безопасность устройства выше удобства → сеть только у ведущего, исполнитель под печатью в обоих контурах; сомкнутый без печати и без `unshare` не запускается. |
| 2. Архитектурно или заплатка | «Сеть у песочницы» — класс (любой процесс исполнителя), поэтому печать на процесс, а не проверка в переходнике. Ключ — тоже класс (любой файл прогона): живёт только в памяти ведущего, проверяется поиском по байтам. |
| 3. Готовое | Исполнитель, агент, `Driver`, `one()`, наблюдатели, строгая проба §18 — свои, проверенные; повторно не пишутся. Описания законов — из словарей наблюдателей. Класс снаружи: «seccomp network deny», «Ubuntu 24.04 unprivileged user namespaces restricted» (из памяти; второй такт — проверка на этой машине и в тестах). |
| 4. Границы | Объявляются: полномочия (сеть только у ведущего), данные (ключ не в файлах; токены — со слов поставщика, не замер), ресурс (бюджет прежний; деньги поставщика вне бюджета), безопасность (127.0.0.1 и метка). Закреплены тестами на молчание: без печати сомкнутый не идёт; ключа нет в файлах. |
| 5. Куда ошибётся | Связь терминальна (вопрос уходит наружу): сомнительное не отправляется — проверка до отправки делает исполнитель, как раньше. Сбой облака — в сторону молчания (−7), а не выдуманного ответа. |
| 6. Чем видно | Строка хода со счётчиком секунд; «модель молчит (−7)» с причиной от связи; пометка «печать не поставлена»; аудит процесса. Проверка установки — прибор: её ходы известны, и прогон без модели показывает, что устройство работает. |
| 7. Что не сливать | Связь и передатчик: передатчик без сети и без ключа, связь без доступа к песочнице. Слито — сеть и ключ оказались бы у процессов исполнителя, и их утечку не увидел бы никто. Экран и исполнитель — разные процессы, как с шага 5. |
| 8. Чего не умеет | §8, §9 и строки в начале каждого файла `app/`. |
| 9. Условие включения | Сомкнутый — только при печати или `unshare`; разомкнутый — при ответе проверки связи. Материал — вопросы агента 1–4096 байт; слова человека до 600 байт. |

# 12. Агент: два языка и свой агент (решение владельца 19.11)

**Встроенный агент — двуязычный.** Агент agent9 собирается из одного
исходника в двух видах: с правилами для модели по-русски или
по-английски (ключ сборки `LANG_EN`). Язык правил выбирается при запуске
(по умолчанию — язык экрана). Ходы оба вида понимают на обоих языках:
`ЧИТАЙ ЗАДАНИЯ` и `READ TASKS`, `ВЫЗОВ` и `CALL`, `СТОП` и `STOP` и т. д.;
итоги в истории — на языке правил. Среда не меняется: те же ворота, цены
и законы.

Русский вид отличается от прежнего agent9 только тем, что понимает ещё и
английские ходы: правила, итоги и вопрос модели — байт в байт прежние.
Ответ модели, который прежде был «нет такого хода» (например, `STOP`),
теперь ход. Прежние прогоны таких ответов не содержат (проверено поиском
по тестам), их итоги в силе.

**Свой агент.** Человек загружает свою программу WebAssembly (`.wasm` или
текстом `.wat`) — она живёт в песочнице вместо встроенного агента. Для
среды это обычный агент шага 5: модуль с импортами только `env.call` и
`env.spawn`, точка входа `main`, память не больше предела исполнителя.
Модуль с другими импортами не загружается — это закон И23р, и он
проверяется на загруженном агенте так же, как на встроенном. Экран
проверяет модуль заранее (импорты, `main`, размер до 1 МБ), чтобы
человек увидел причину отказа до прогона, но решает исполнитель.

Свой агент спрашивает модель тем же ходом — `call(8, 2, адрес, длина)`
(номер 8 — модель в его таблице): вопрос оплачен и записан до отправки,
ответ ложится на место вопроса, не длиннее предела. Устройство вызовов
для автора агента — `docs/svoy_agent.md` (по-английски —
`docs/own_agent_en.md`), пример — `experiments/agents_own/`.

Экран показывает у своего агента вопросы и ответы модели и всё, что
сделала среда; строку «что значит ход» — нет: формат ответа модели
определяет сам агент.

**Чего не умеет:** свой агент — один модуль на прогон (второй агент —
такой же или «не ходит»); загруженные модули лежат в папке `agents` и
экраном не удаляются; подпись и происхождение модуля не проверяются —
его не нужно доверять: он в песочнице.

**Проверки (объявлены до кода).**

| Что | Как | Вердикт |
|---|---|---|
| русский вид | весь прежний набор тестов agent9 | проходит без правок |
| английский вид | облако-заглушка отвечает английскими ходами | ходы сделаны, итоги английские, законы соблюдены |
| ходы на чужом языке | русский вид, ответ `READ TASKS`; английский вид, ответ `ЧИТАЙ ЗАДАНИЯ` | оба сделаны |
| разборщик экрана | `move_of` на английских ходах | тот же ход, что у агента |
| свой агент, верный | пример на `.wat` спрашивает модель и пишет снимок | законы соблюдены; вопрос в журнале |
| свой агент с чужим импортом | модуль импортирует `wasi_snapshot_preview1.fd_write` | экран отказывает до прогона; исполнитель — тоже (И23р) |
| свой агент без `main` | модуль без экспорта `main` | отказ до прогона |
