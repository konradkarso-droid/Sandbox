# Папка обмена и файловые инструменты

В интерфейсе открой «Файлы обмена» → «Создать папку».
Положи файлы в показанный `inbox` или добавь их через экран. Запусти
агента. Свой Wasm в локальном профиле можно запустить без модели.
Для облака выбери провайдера из списка и конкретные версии файлов в
разделе обмена, затем подтверди отправку. Подробно — [облачный шлюз](cloud_gateway.md).

После проверки законов экран показывает оплаченные заявки. Кнопка
«Подтвердить выдачу» действует на одну конкретную версию файла. Результат
появляется в `outbox/<номер>-<имя>`, квитанция в `receipts/<номер>.json`.
Квитанция содержит SHA-256 файла, хеш записи списания, размер и цену.
Существующий файл с другим содержимым остаётся на месте, выдача сообщает
об ошибке. Повтор подтверждения дописывает квитанцию после сбоя и
сверяет уже выданные байты. После перезапуска приложение открывает
последний выбранный сеанс. Другой сеанс можно открыть по номеру папки.

## Граница и цена

- Локальный профиль импортирует весь `inbox`. Облачный профиль импортирует
  только подтверждённые версии файлов. Разрешение действует для одного
  сеанса и выбранного провайдера.
- `inbox` импортируется один раз на старте. Вход — плоский набор до 16
  обычных файлов, по 64 КиБ на файл и до 256 КиБ суммарно. Имя занимает
  до 120 байт UTF-8. Версия фиксируется для каждого файла в момент его
  копирования. Снимок не является общей атомарной версией папки.
- Только первый контур получает полномочие на обмен. Его помощники
  работают с тем же бюджетом и теми же данными. Второй контур использует
  прежние полномочия.
- Исполнитель хранит содержимое отдельно от папки пользователя. Для
  импортированных файлов и всех сохранённых версий черновиков отведено
  до 4 МиБ на сеанс. Пределы заданы в `env/exchange.py`. Это
  объявленные квоты первого профиля. Замеры физической стоимости
  чтения и записи в эти числа не входят.
- В рабочем профиле `paid_attempts=1` и `M3`. Отказы тарифицируют прежние
  ворота. При нуле остатка срабатывает останов по И33р.
- Сведения в квитанциях и диагностике доступны владельцу. Закрытое
  файловое хранилище не входит в диагностический ZIP. В журнале
  локальных запросов модели могут быть данные, переданные ей агентом.

Импорт использует имя внутри уже открытого каталога и отвергает ссылки
и специальные файлы. Получатель создаёт цель только после записи целого
временного файла и синхронизации его содержимого. [open(2)](https://linuxman7.org/linux/man-pages/man2/openat.2.html) · [CWE-59](https://cwe.mitre.org/data/definitions/59.html)

## ABI агента

Справочник `call(5, 2, a, b)` по имени `files` возвращает индекс уже
выданного полномочия. В первом контуре это 8 без модели или 9 с моделью.
Вызов `call(cap, 9, a, b)` читает в памяти по адресу `a` заголовок из
четырёх байт `u32le` с вместимостью ответа, затем объект JSON UTF-8.
`b` включает заголовок. Запрос и вместимость ответа ограничены 4096
байтами. Успех возвращает длину JSON-ответа, записанного по адресу `a`.
Отрицательный код — отказ ворот. Встроенный агент передаёт тот же JSON
командой `ФАЙЛЫ` или `FILES`.

| Инструмент | Поля помимо `tool` | Результат | Цена успеха |
|---|---|---|---|
| `files.list` | `offset` по желанию, первый — 0 | До трёх файлов, следующее смещение в `next` | `g` |
| `files.read` | `id`, `offset`, `length` от 1 до 2048 | `data` в base64 и признак `eof`. Для встроенного агента используйте порции до 256 байт. | `g` |
| `files.search` | `id`, `offset`, `needle` в base64, от 1 до 64 байт | Байтовое смещение первого совпадения или `null` | `g` |
| `files.write` | `name`, `offset`, `data` в base64 | Размер новой версии. Нулевое смещение начинает файл заново, ненулевое совпадает с концом черновика. | `2g` за списание и квитанцию черновика |
| `files.publish` | `name` черновика | Номер заявки на выдачу конкретной версии после подтверждения владельца | `c`, цена фиксации |

`g` и `c` берутся из действующих настроек среды. Повтор заявки на ту же
версию получает платный отказ. Человек подтверждает уже оплаченную
публикацию. Запись и квитанция черновика разделены: после сбоя незаконченная
запись остаётся оплаченной, а версия получает право на выдачу только
после квитанции.

## Приёмка

Тесты `tests/test_exchange.py` проходят через агента WebAssembly, прежние
ворота и получателя с отдельной квитанцией. И1р сверяет расход и остаток,
И32р и И33р — отказы и останов, И35р — цены файловых вызовов, снимок,
черновики и заявки. Проверяются восстановление между списанием и
квитанцией, конфликт выдачи и отказ после изменения проверенного журнала.
Отдельный прогон проверяет команды встроенного агента с записанными
ответами модели через локальный канал. Для живого GGUF требуется
Bubblewrap и [положительная приёмка на Linux](gguf_acceptance.md) с доступными пространствами имён.

### Параллельные сеансы и лимиты

Сквозной тест запускает два экземпляра приложения одновременно с
локальными HTTP-получателями. В обоих сеансах входной файл и черновик
имеют одинаковые имена, а содержимое различается. Каждый получатель
видит только байты своего снимка. При совпадающих номерах заявок
подтверждение первого сеанса открывает только его файл.

В файловом профиле WebAssembly получает две страницы линейной памяти
(128 КиБ). Тест подтверждает рост с одной до двух страниц и отказ
в третьей. При исчерпании вычислительного топлива исполнитель
завершается, а записанный черновик остаётся без заявки и выдачи.
Отдельный тест подтверждает, что по истечении срока ответа процесс
модели-заглушки завершается.

Квота хранилища проверяется на фактическом пределе 4 МиБ. После
повторного открытия хранилище принимает ссылку на уже сохранённое
содержимое и отклоняет новые байты, сохраняя прежние версии.
Проверки относятся к линейной памяти WebAssembly, сроку ответа и
квоте файловых версий. Физические лимиты RAM и диска для процесса
GGUF требуют отдельного измерения.

В локальном прогоне `tests/test_app.py tests/test_exchange.py tests/test_gateway.py`
прошли 70 тестов, включая все проверки выше. Один тест Bubblewrap
пропущен из-за ограничения Linux на настройку таблицы идентификаторов
пользователя. Облачный API в этом прогоне не использовался.
