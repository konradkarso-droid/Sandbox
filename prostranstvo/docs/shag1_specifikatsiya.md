# 1. Что проверяет шаг и чего не проверяет

**Проверяет:** звенья Л1–Л3 (связь, независимость, ограничение) в варианте
M1 — общий бюджет и фиксированная цена. Гипотезы У1–У5. Сценарий 0.3 §56:
агент пытается получить результат без списания.

**Не проверяет:**

- **Л4.** Здесь недостижимость получателя при B < c следует из объявленной
  цены, то есть это ограничение ценой, а не ресурсная трудность (0.1
  §21). Л4 — шаг 3.
- **Полезность (Л5).** Шаг 4.
- **Физику, каналы, LLM.** Шаги 6–8.

# 2. Формализация

*(«Пространство», этап 1)*

| Вопрос | Ответ для шага 1 |
|---|---|
| Что считается элементом | исполнитель (доверенный), основной работник агента, помощники (до K), получатель |
| Что считается состоянием | W = (X, G, H, b, O) в конечной форме, см. §3 |
| Что считается изменением | одно действие из перечня §4, выполненное исполнителем |

| Что считается опровержением | достижимое состояние или переход, где нарушен хотя бы один закон; в частности, состояние «получатель изменён, а списано меньше c на доставку» |

# 3. Состояние

| Часть | В модели | Кто меняет |
|---|---|---|
| X | у каждого работника: черновик (какое сообщение готово к отправке) и один снимок черновика | агент |
| G | кто жив из помощников; полномочие пополнения бюджета есть только у исполнителя и агенту не выдаётся | исполнитель |
| b | остаток, разложенный по работникам: доля[w] ≥ 0; сумма долей = общий остаток | исполнитель |
| H | журнал как сводка: число записей, записанный расход, записанные доставки по каждому сообщению | исполнитель |
| O | получатель: сколько раз доставлено каждое сообщение | только фиксация |
| — | расход: сколько списано за сеанс (счёт исполнителя) | исполнитель |

Сообщений два: «А» и «Б». Пакетная отправка нужна, чтобы проверить,
оплачивается ли пакет целиком.

# 4. Действия

Внешнее действие одно: **фиксация** — доставка черновика получателю. Оно
бывает трёх видов исполнения: одиночное, пакетное, прерванное сбоем.
Остальные действия внутренние.

| Действие | Вид | Цена | Эффект в правильном исполнителе |
|---|---|---|---|
| подготовить(w, m) | внутр. | 0 | черновик w := m |
| снимок(w) | внутр. | 0 | снимок w := черновик w |
| откат(w) | внутр. | 0 | черновик w := снимок w; доли и расход не меняются |
| создать помощника | внутр. | 0 | новый работник с долей 0 |
| завершить(h) | внутр. | 0 | доля h возвращается основному работнику; h удалён |
| передать(w₁, w₂) | внутр. | 0 | доля w₁ − 1, доля w₂ + 1 |
| назвать полномочие(w, «пополнение») | внутр. | 0 | отказ: знание имени права не даёт (A3, A9) |
| перезапуск | внутр. | 0 | помощники удалены, их доли возвращены основному; черновики и снимки стёрты; доли, расход, журнал и получатель сохраняются (A5) |
| фиксация(w) | внешн. | c | если черновик есть и доля ≥ c: доля − c, расход + c, получатель + черновик, запись в журнал. Иначе отказ: получатель не меняется, списывается c_отк |
| пакет(w) | внешн. | 2c | доставка «А» и «Б» одним действием, если доля ≥ 2c; иначе отказ |
| фиксация со сбоем(w) | внешн. | 0 или c | сбой внутри фиксации, три исхода: «ничего» (упавший исполнитель ничего не списывает), «списано, не доставлено», «оплачено и доставлено». Исхода «доставлено, не списано» нет (§4.5 концепции) |

Внутренние действия бесплатны **нарочно**: это самая выгодная для
противника настройка. Если учёт держится при бесплатной внутренней работе,
он держится и при платной.

**Поправка при шаге 2.** В первой редакции у сбоя было два исхода, и
«ничего» брало c_отк. Сверка с реализацией показала, что исходов три и что
упавший исполнитель платы взять не может. Модель поправлена, перебор
перезапущен (отчёт шага 2).

# 5. Законы

| Закон | Проверяется | Формулировка | Концепция | Гипотезы |
|---|---|---|---|---|
| И1 | в каждом состоянии | сумма долей + расход = B₀; все доли ≥ 0 | З1 | У1, У2 |
| И2 | на каждом переходе | внутреннее действие не меняет получателя | З2 | — |
| И3 | на каждом переходе | если получатель вырос на k доставок, в этом же переходе расход вырос не меньше чем на k·c | З3 | У3, У4 |
| И4 | на каждом переходе | отказ не меняет получателя | З4 | У3 |
| И5 | в каждом состоянии | журнал сходится: записанный расход = расход; записанные доставки = получатель | З5 | У5 |
| И6 | в каждом состоянии | **результат без списания:** c × (всего доставок) ≤ расход | З3 | У3, У4 |
| И7 | на каждом переходе | журнал только растёт: число записей и записанные суммы не уменьшаются | З5 | У5 |
| И8 | на каждом переходе | внутреннее действие не увеличивает общий остаток | З1 | У1, У2 |

**Почему И3 и И6 обе нужны.** Это одна мысль на двух масштабах.

- **И6** смотрит на итог. Она ловит бесплатную доставку при c_отк = 0. Но
  если неудачные попытки тоже стоят денег, бесплатную доставку можно
  «спрятать» за оплаченным отказом: итоговый расход тогда сходится.
- **И3** смотрит на каждый шаг отдельно, и такая маскировка её не
  обманывает.

**Цель противника** из 0.3 §56 — достичь состояния, где нарушена И6, то
есть получить доставку, не заплатив за неё.

# 6. Противник

Противник — **полный перебор всех последовательностей действий** из любого
начального состояния, в пределах параметров. Любой конкретный агент, в том
числе языковая модель, — лишь одна из этих последовательностей. Поэтому
«нарушений нет» для перебора сильнее, чем «агент не справился».

Перебор идёт в ширину, поэтому первый найденный контрпример — **самый
короткий**.

# 7. Проверка самой проверки: испорченные исполнители

Молчание перебора («нарушений нет») ничего не стоит, пока не показано, что
перебор видит нарушение там, где оно есть. Поэтому в исполнитель встроены
двенадцать порч, включаемых по одной. Каждая повторяет известный класс ошибок
учёта. Включённая порча обязана быть поймана, и на каждый из восьми законов
есть хотя бы одна порча, которую ловит именно он: закон, ни разу не
сработавший, ничем не отличается от сломанного.

| Порча | Что сломано | Какой закон обязан сработать | Откуда класс |
|---|---|---|---|
| Б1 | откат восстанавливает и долю из снимка | И1, И8 | 0.1 опыт 2 |
| Б2 | помощник получает копию доли основного | И1, И8 | A4 |
| Б3 | при нехватке доли доставка проходит, а списание нет | И3, И6 | 0.3 §38.2 |
| Б4 | пакет оплачивается как одна фиксация | И3, И6 | 0.2 опыт 3 |
| Б5 | сбой между доставкой и списанием: доставлено, не списано | И3, И6 | 0.1 опыт 6 |
| Б6 | названное имя полномочия срабатывает: доля + 1 | И1, И8 | A3 |
| Б7 | перезапуск возвращает основному полный бюджет | И1, И8 | A5 |
| Б8 | повторная доставка уже оплаченного сообщения бесплатна («из кеша») | И3, И6 | 0.3 §46 п.6 |
| Б9 | агент может стереть последнюю запись журнала | И5, И7 | 0.3 §45.2 |
| Б10 | передача добавляет получателю, не отнимая у отдающего | И1, И8 | 0.1 опыт 1 |
| Б11 | перезапуск отзывает уже доставленное у получателя | И2, И5 | A7 (доставленное откатом не отменяется) |
| Б12 | сбой фиксации оставляет доставку при записанном отказе | И4, И3, И6 | A7, 0.1 опыт 6 |

Порчи живут в коде только для этого. В правильном исполнителе все
выключены.

# 8. Параметры и конфигурации

Параметры — данные, а не код: `experiments/shag1.yaml`.

| Параметр | Значения в серии | Смысл |
|---|---|---|
| B₀ | 0…6 | бюджет сеанса |
| c | 1, 2, 3 | цена одной фиксации |
| c_отк | 0, 1 | цена неудачной попытки |
| K | 0, 1, 2 | наибольшее число помощников |
| потолок доставок | ⌊B₀/c⌋ + 1 на сообщение | граница перебора: на единицу выше, чем позволяет бюджет, поэтому правильный исполнитель в неё не упирается, см. §10 |

Все числа **объявлены, а не подобраны**: это малые значения, при которых
полный перебор заканчивается за секунды. Пропущено одно сочетание — два
помощника при цене 1 и бюджете выше 4 (объявленная граница по времени).

Порчи проверяются на одной конфигурации: бюджет 4, цена 2, цена неудачной
попытки 1, один помощник. Случайный обход — бюджет 40, цена 2, цена
неудачной попытки 1, до трёх помощников, 30 зёрен по 3000 шагов.

# 9. Откуда берётся каждая стоимость

- **c** — объявленная константа среды (вариант M1). Физической работы за
  ней нет. Это цена по договору, а не по закону.
- **c_отк** — объявленная константа. Неудачная попытка расход не
  возвращает (A5, §4.5 концепции).
- **Внутренние действия — 0.** Сознательно, в пользу противника (§4).
- **Пакет — 2c.** Он доставляет два сообщения. Обязательная работа равна
  сумме одиночных: в M1 оптимизации пакета нет.

# 10. Чего модель не умеет

- **Журнал — сводка.** Число записей и суммы. Порядок записей и подмена
  записи на равную по сумме не моделируются.
- **Один ресурс.** Память, время и энергия не учитываются.
- **Перебор ограничен.** Малые параметры (§8) и две границы: потолок
  доставок и остановка на состоянии, уже нарушившем закон. Правильный
  исполнитель ни в одну не упирается, и это проверяется в каждом прогоне.
  За пределами параметров — случайный обход: он наблюдает, но не
  доказывает.
- **Доля в снимке хранится только при порче Б1.** Правильный исполнитель
  её не читает, и без неё перебор не размножает неразличимые для законов
  состояния.
- **Сбой только внутри фиксации.** Сбой посреди передачи доли или
  перезапуска не моделируется: эти действия считаются атомарными по
  построению.
- **Параллелизм — чередованием.** Помощники действуют по очереди в любом
  порядке. Одновременное исполнение одного действия двумя работниками не
  моделируется — значит, и гонки учёта на уровне реализации не ловятся.
  Это шаг 2.
- **Л4 и Л5 не затрагиваются** (§1).

# 11. Прогон по CHECKLIST.md

Прогон по открытому файлу `CHECKLIST.md` репозитория agent-mobile. Пункты
чек-листа — правила строящего, и они применимы и к этому проекту.

| Пункт | Ответ |
|---|---|
| 1. Безопасность и цена | Платим грубостью модели (сводка журнала, один ресурс) ради полного перебора. Физики нет, телефон не трогается, нагрузка — секунды на сервере. При ничьей порядок такой: безопасность устройства, затем целостность учёта, затем полезность. |
| 2. Класс или случай | «Результат без списания» — **класс**: любой путь мимо учёта. Поэтому проверяем перебором всех путей, а не тестом на один сценарий. |
| 3. Готовое | Снаружи это два известных класса: явный перебор состояний (explicit-state model checking: TLC для TLA+, SPIN) и мутационное тестирование (проверка проверок порчами). Имена из памяти, знание устойчивое, в сети не сверялось. В проекте agent-mobile есть правило «тесты на молчание». Взят принцип, а не код. TLA+/TLC — кандидат на вторую независимую реализацию (шаг 5). |
| 4. Угадываю или объявляю | **Объявляю.** Цены и пределы перебора — объявленные числа, записаны в одном месте (конфигурация) и закреплены тестами. Полномочия: пополнение есть только у исполнителя. Данные: «расход» — счёт исполнителя, а «доставки» — наблюдение получателя; это разные источники. Безопасность: ни сети, ни файлов вне папки проекта. |
| 5. Куда ошибётся | Вывод «нарушений нет» — терминальный: промах в сторону пропуска даёт ложную уверенность и невосстановим. Значит, сомнительное должно поднимать тревогу. Отсюда **порчи** (§7) и законы на двух масштабах (И3 и И6). |
| 6. Чем видно | «Нечего ловить» отличается от «не умеет ловить» тем, что все двенадцать порч пойманы, и каждый закон хоть раз сработал. Вывод по-русски: самый короткий путь-контрпример по шагам плюс CSV. |
| 7. Что не слить | (а) Счёт исполнителя и наблюдение получателя. Если их слить, порча, подделывающая счёт, станет невидимой. (б) Проверку по состоянию (И6) и по переходу (И3): без И3 не видна бесплатная доставка, спрятанная за оплаченным отказом. (в) «Доказано перебором» и «наблюдалось случайным обходом» в отчёте. |
| 8. Чего не умеет | §10 этого документа и строки в коде рядом с механизмом. |
| 9. Условие включения | Перебор включается на конфигурации из §8 и покрывает только малые параметры. Большие — только случайный обход, и он даёт наблюдение, а не доказательство. |

**Что прогон переставил:**

- **Добавлены испорченные исполнители (пп. 5, 6).** Без них «нарушений
  нет» — непроверенное молчание. Первые десять порч не задели законы И2 и

- **Добавлены законы на переходах (п. 7).** Изначально были только
  проверки по состоянию.
- **Добавлен случайный обход для больших параметров (п. 9).** С явной
  пометкой: это наблюдение, а не доказательство.
- **Счёт исполнителя и наблюдение получателя разведены (п. 7).**
- **Проверка через TLA+ отнесена к шагу 5 (п. 3).** Её место — вторая
